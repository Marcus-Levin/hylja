## Route and profile discipline

Each fixture carries a *proposed*, #2-shaped interaction with synthetic `subject.principalId` (no adapter-only `surface`), `source.ref` = public fixture ID, `destination.ref` = proposed capture ID, tenant/project/session/purpose and representation. `mediaType` is bare `text/plain` or `application/json`; UTF-8 is recorded separately in `encodings`. The proposed #4 profile uses exposure `EXTERNAL` (with `LOCAL` reserved for separately authorized local controls), not an invented `simulated-external` enum. These refs/fields are fixture descriptions, **not authenticated provenance or a resolved profile**. `bindingStatus` is explicitly unauthenticated and `actualRoute` is `not-observed`, with `observedSinkId`/`observedProfileId` null; `plannedControlledSinkId` names only a proposed local capture target, not network permission or evidence of interception. The future #5 seam must establish authenticated context and bind the **actually routed** sink/profile after routing; missing/mismatched context, unsupported representation or unchecked mutation cannot turn a fixture's proposed profile into release authority. No real protected data or third-party network requests belong in this draft. An external semantic judge, if introduced later, requires a separate destination decision and final-byte check.

**Future fixture → runtime mapping (not implemented):** #5 may form a validated #2 envelope from `interactionProposal` plus `input` only after a trusted runner supplies envelope version/ID/time, actual authenticated principal and tenant/purpose/session binding, source provenance and observed routing. Join D02 log lines with a pinned LF rule and serialize D05 JSON with a pinned UTF-8 rule; neither serialization rule is frozen here. Do not copy `bindingStatus`, `destinationProfileProposal` or planned capture IDs as security authority. Resolve #4's effective `EXTERNAL` profile from the actual sink and compare it with the proposal; mismatch, absent context/profile or an unobserved route cannot authorize protected release. No evaluator adapter or runtime profile is provided by this document.

## Treatment/fidelity matrix for review (not per-occurrence oracle)

All rows are **proposals conditional on reviewed classification and trusted bindings**, not automatic actions or a policy table. For an unknown class or absent actual destination, no `KEEP` is implied. `BLOCK` is terminal and `REQUIRE_REVIEW` holds with zero bytes until separately authorized; neither transforms content. `SYNTHETIC`/`TOKENIZE` for reversible originals would require the later scoped broker, not a plaintext development mapping. In this non-enforcing comparison, any stand-in is disposable synthetic text, not a restored original.

| Reviewed category | Proposed simulated external model profile (`PROFILE-DEMO-EXTERNAL`) | Arbitrary/unknown external destination | Fidelity question to resolve before lock |
| --- | --- | --- | --- |
| `PERSON.NAME`, `PERSON.EMAIL`, `PERSON.PHONE`; `CUSTOMER_OR_PARTNER`, `PROJECT_OR_CONTRACT` | Consider `SYNTHETIC` or `TOKENIZE` only if a reviewed destination permits a safe representation; otherwise `MASK`, `REQUIRE_REVIEW` or `BLOCK`. Never infer email/phone ownership solely from format. | `BLOCK` or `REQUIRE_REVIEW` for protected data, not plaintext fallback. | Keep primary/backup roles and customer/project relations coherent relative to the candidate-visible transformed input; do not require raw names or contact coordinates in task answers. |
| `USER_ACCOUNT`, `HOST_OR_SERVICE`, `NETWORK_IDENTIFIER.IP`, protected `FILE_OR_RESOURCE_PATH` | Consider consistent `SYNTHETIC`/`TOKENIZE` or safer `MASK` according to classification and sink; not an automatic reversible mapping. | `BLOCK`/`REQUIRE_REVIEW` for protected data. | Preserve needed endpoint relationship and absolute Linux output-file path *semantics* relative to candidate-visible transformed input, never forbidden original spelling. |
| `CREDENTIAL_OR_SECRET` (including a recognized token/key-shaped field) | `BLOCK`, or irreversible `MASK`/`REMOVE` **only** if a separately reviewed continuation remains safe; no reversible credential map. | `BLOCK`. | Never trade credential release for task success; a visibly non-live fixture string is not release authorization. |
| `NETWORK_IDENTIFIER.PORT`, protocol/OS/syntax tokens and unprotected structural keys | `KEEP` only after reviewed field sensitivity and destination approval; if part of a protected combination, apply the reviewed safer treatment. | No blanket `KEEP`: require an actual profile/policy decision. | Preserve 443 versus 8443 diagnosis (D02) and consistent HTTPS effective port 443, JSON structure and Linux path semantics (D05). |
| `UNKNOWN`, conflict, parser failure, missing trusted route/context or uninspectable content | Restrictive `BLOCK` or `REQUIRE_REVIEW`; do not emit an unmodified protected payload. | `BLOCK`/`REQUIRE_REVIEW` with no release. | A held/blocked attempt has no successful downstream task outcome. |

There is **no authorized local USE/DISPLAY/EXPORT test in these three fixtures**; no claim of restoration or brokered release follows from this matrix. A trusted local synthetic task control is not an external-release exception. Sensitivity is distinct from influence trust; fixture-supplied tenant/profile text is data, not `CONTROL` provenance.

## Scoring proposal for the later #5 seam

| Dimension | Proposed measurement and failure accounting |
| --- | --- |
| Candidate source, independent of judge/policy/sentinel | By class and separately NAME/EMAIL/PHONE: TP, FN, FP, recall `TP/(TP+FN)`, precision `TP/(TP+FP)`, subtype confusion and false-cloak/lookalike counts. Agree one-to-one field/span/normalization matching with independent oracle before tuning; zero denominators yield `n/a`. A later semantic judgment or sentinel catch cannot erase a missed candidate. |
| Decision and actual release | Compare expected treatment/fidelity per observed destination with independent oracle. Separately count primary-path attempted escapes stopped by sentinel, forbidden planted originals in **exact post-serialization bytes actually delivered** to a controlled sink (body, headers, metadata, errors, chunks; bounded encoding equivalents), and unobserved/bypassed surfaces. Report per-class planted containment denominator and absolute critical escapes; a blocked/held request sends zero bytes but does not score as a solved task. No run or sink capture exists here. |
| Engineering utility | Apply only the fixture's predeclared task predicates: D01 primary→backup ordering/channel without contact coordinates; D02 attempted 443 vs expected 8443, HTTPS and `/health`; D05 valid JSON, consistent HTTPS effective port 443 with `/v1/ping`, literal-safe `os=linux` and `timeoutMs=2500`, plus customer/project/host entity continuity and absolute Linux output-path semantics judged against candidate-visible transformed input, not raw original spelling. Report task correctness, syntax, over-cloaking and abstention separately from privacy; do not require original protected spelling after cloaking. |
| Coverage and operations | Per surface/role, explicit tested/untested/unsupported/outside-architecture status and bypass/failure case; latency/throughput, model/API/compute cost, setup effort and human interventions only when independently measured. Evidence provenance (`claim/docs`, `source-inspected`, `vendor-demonstrated`, `independently-executed`, `untested`) is separate from observed outcome (`pass`, `fail`, `observed-only`, `passthrough`, `unsupported`, `outside architecture`); `untested` has no observed outcome. |

**Proposed hard gates:** any forbidden SECRET plaintext delivered to a tested disallowed sink, unauthorized restoration/cross-tenant resolution, or falsely claimed interception blocks a pass for that role regardless of utility or averages. Exact failure/abstention attribution, class/destination gates, aggregation weights (or an explicitly unweighted comparison), span matching and denominator rules still require independent review and public lock **before any candidate tuning**. They are deliberately not invented as a final protocol here. Do not treat zero observed escapes from an unexecuted fixture as a pass.

**Pending after independent DEV oracle-content review:** destination/policy approval of proposed occurrence treatments and fidelity, task/rubric lock, independently controlled blind partition outside candidate access, agreed/public scoring and integrity-recorded pre-tuning baseline. The separate DEV oracle draft is not an authorization rule or locked benchmark; no blind oracle is exposed here. A *separate* scored v0 freeze waits for the minimal executable #1/#5 seam to process reviewed oracle, destination treatments and at least one task end to end, capture actual serialized sink bytes and pin/hash the real corpus/oracle/policy/tasks/split/scoring/runner. No v0 hash, score, tuning, runtime enforcement or #39 completion is asserted. Ordinary reports/CI must contain allowlisted counters and opaque IDs, not planted originals, raw task payloads or reversible maps; these explicit public development-only fixture/oracle drafts contain only visibly synthetic planted data, not ordinary run output.
