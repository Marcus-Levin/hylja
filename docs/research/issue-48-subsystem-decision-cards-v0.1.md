# #48 subsystem decision cards v0.1 — source-scope proposal quality

**Desk supplement to [#48](https://github.com/Marcus-Levin/hylja/issues/48), written 2026-10-01 (UTC) by static public-source inspection. Not independently reviewed. Not adoption.**

This document fills [#48](https://github.com/Marcus-Levin/hylja/issues/48)'s nine *decision-quality* fields for **all sixteen** subsystems at the only scope available today — **source and document text read at pinned immutable commits**, plus Hylja's own accepted design documents. It records **proposal quality**, not decision completion: every card separates what a pinned source or document *literally provides* from what remains **unproven at runtime**, and no card contains a measurement, a pass, a winner, an adoption or an accepted decision.

It does **not** freeze [#39](https://github.com/Marcus-Levin/hylja/issues/39), approve a component, declare any candidate enforcing, or change accepted architecture, decision [010](../decisions/010-separate-information-dimensions-and-task-fidelity.md) or the taxonomy/dimensional drafts, which stay **PROPOSED**. Current capabilities and limits live only in [docs/capabilities.md](../capabilities.md) and live task status only in the GitHub issues; the dated record for these cards is the retired plan's [frozen snapshot](https://github.com/Marcus-Levin/hylja/blob/f838fc2dc8da0402338d4dfd1c028392a9f4b9ee/docs/plan.md#current-state), not current state. Companions: the [role/surface dossier](issue-38-48-role-surface-conformance-dossier-v0.1.md) (fact ids `P#`, `O#`, `K#`, `C#`, `L#` and the conformance matrix), the [reconciliation table](issue-38-48-affected-issue-reconciliation-v0.1.md) (per-issue dispositions), the [candidate register](issue-38-46-candidate-register-v0.1.md) (identity/licence/tier, owned elsewhere — **not edited here**), the [Presidio selected-artifact dossier](https://github.com/Marcus-Levin/hylja/blob/main/docs/research/issue-46-presidio-artifact-prescreen-2026-10-01.md) at commit `08ed7bb`, and the [synthetic development-only test plans](issue-43-68-synthetic-dev-test-plans-v0.1.md).

## 0. Method, and the limits every card inherits

* **Nothing was executed.** No candidate binary, package, model weight, container, proxy or endpoint was installed, imported, run or contacted; no vendor was contacted; no account was procured; no trust store was changed; no protocol was frozen; no comparison was scored. Under [#38](https://github.com/Marcus-Levin/hylja/issues/38)'s two axes, every `source-inspected` or `claim/docs` fact below has **no observed outcome**. `untested` means evidence was not established — not that a capability or a risk is absent.
* **Scope of the negative claims.** "No candidate provides X" means: *within the files read for the dossier at the listed pins* (Presidio analyzer/anonymizer sources and default config; OPF label space, checkpoint loader, runtime, API/CLI surface; Kiji proxy, PII store, mapper, streaming and telemetry; CloakPipe vault, MCP crate and shipped policy; LiteLLM Presidio and hosted-Jev guardrails), no such mechanism was observed. It is a **bounded source-desk negative, not a whole-repository or whole-product negative**, and it is never a pass.
* **Correction carried by this supplement (root finding R1).** An earlier draft turned *absence of Hylja-specific semantic labels* into *absence of detection capability*. That is wrong, and this document states the corrected position: at the pinned Presidio commit the generic recognizer set **does** include `IP_ADDRESS`, `MAC_ADDRESS` and `URL` (dossier **P7**, **P8**), and OPF's `v2` taxonomy **does** include generic `private_address`/`private_url` labels (**O1**). That is **overlapping syntactic recognition of address-shaped and URL-shaped strings**. It is *not* Hylja's semantic role, privacy attribute, sensitivity/trust evidence, bounded provenance, source-to-sink authority, or a measured recall figure — and **registration is not efficacy**: the emitted score is a pattern confidence constant with caller-owned thresholds (P4, P8), so nothing here evidences recall or precision.
* **Fixture-design caveat inherited by every card.** Hylja fixtures use reserved suffixes (`.invalid`, `example.com`, documentation IP ranges). At the pinned Presidio commit the `UrlRecognizer` suffix enumeration contains **no** reserved suffix (dossier **P8**), so an arm evaluated only on `.invalid` hosts would report **zero** URL hits and could be mistaken for detector quality. Any later #40/#45 arm must use **paired** fixtures — the same host shape under a reserved suffix that the recognizer cannot match (`db-customer-a.example.invalid`) **and** under an IANA-documentation suffix that it can (`db-customer-a.example.com`) — and must not score URL/host cells that rest on reserved suffixes alone. Both sides stay obviously synthetic and non-routable; no real registered domain is introduced. This is a design requirement for future work, **not** a result: nothing was executed.
* **Field-filling rule.** Each card states, per field, either a source/document fact with an immutable citation, or `unknown — untested`. Where a field could only be filled by execution, it says so and names the test that would fill it. No field is filled by estimating, extrapolating or deferring the question to "later review" without naming what later means.
* **Counterexample-first rule.** Requirement 4 of each card names a concrete synthetic counterexample that would falsify the proposal, or, for `build` choices, a concrete regression the accepted tests already or must cover. Synthetic values are `.invalid`/`example.com`/documentation ranges only.

### Field definitions ([#48](https://github.com/Marcus-Levin/hylja/issues/48), verbatim order)

1. **Evidence source and tested version** — pinned commits/paths actually read; `tested: none (UNEXECUTED)` unless an executed test exists, in which case the exact test and command are named.
2. **Requirements met / not met** — split into `at source/document scope` (what the pinned text provides) and `unproven at runtime` (never inferred).
3. **Critical counterexample / test gate** — the specific case that would refute the proposal, and the gate that must pass first.
4. **Privacy/security residual risk** — what remains exposed if the proposal is adopted as written.
5. **Utility/fidelity impact** — `unknown` plus the hypothesised test; never a number.
6. **Operational complexity and cost** — qualitative shape only; monetary and runtime cost `UNMEASURED`.
7. **Licensing/maintenance risk** — known vs prescreen-unknown, attributed to the register where it is the owner.
8. **Portability/replaceability** — the narrow contract that would carry a swap, or `none established`.
9. **Simpler alternative** — what was considered and whether it is rejected, deferred or undecided, with the reason.

## 1. The sixteen subsystem decision cards

Each card states the same nine fields in [#48](https://github.com/Marcus-Levin/hylja/issues/48)'s order. The card number matches [#48](https://github.com/Marcus-Levin/hylja/issues/48)'s own subsystem number; the `(#N)` suffix names the Hylja issue that owns that subsystem.

### 1. Authenticated interaction envelope, provenance and trusted-context binding (#2)

**Proposed choice: build (Hylja-specific).** Proposal only.

1. **Evidence source and tested version.** Requirements: [security-model.md](../security-model.md#identity-and-access), invariants 5–7, [architecture.md](../architecture.md#core-ownership), the frozen [#2](https://github.com/Marcus-Levin/hylja/issues/2) body. Implementation evidence in this repository: reviewed non-enforcing envelope head `9b5b80a` ([PR #52](https://github.com/Marcus-Levin/hylja/pull/52)), whose own status text states it checks *congruence/freshness only, not authentication or cryptographic proof integrity*. Candidate evidence: dossier §2 — for every inspected pin the authenticated-trusted-context row reads `src: none` **within the files read**. **Tested:** the repository's own synthetic suite for the envelope module only; **no candidate executed**, so for the comparison there is **no tested version (UNEXECUTED)**.
2. **Requirements met / not met.** *At source/document scope:* met — a versioned envelope schema that binds identity/tenant/project/session/purpose/source/destination/profile, checks proof freshness and rejects forged/stale/mismatched context ([#2](https://github.com/Marcus-Levin/hylja/issues/2) acceptance, [plan](https://github.com/Marcus-Levin/hylja/blob/f838fc2dc8da0402338d4dfd1c028392a9f4b9ee/docs/plan.md#current-state) #2 evidence), plus honest residual documentation. *Not met at source scope, by the module's own statement:* authentication of principals/workloads, cryptographic proof integrity, project-membership verification, effective-route/redirect observation, and deny-before-bytes at a real sink. *Unproven at runtime:* every one of those, in any harness, forever, until #21/#23 exist.
3. **Critical counterexample / test gate.** Documented: **a caller able to fabricate the context argument can fabricate authority**. Gate: an integration test that binds an otherwise-valid envelope to a different principal/tenant/project and to an unobserved redirect, asserting **zero bytes at the sink**; plus a replayed first fragment inside the freshness window.
4. **Privacy/security residual risk.** Confused deputy; route/profile substitution; a time-varying adapter object or JS `Proxy` bypassing snapshot reads (already fixed once, regression-tested — a bounded-behaviour residual, not immunity); replay within the freshness window.
5. **Utility/fidelity impact.** Envelope fields must not leak protected values into provenance text (v1 composer accepts caller-supplied provenance strings that could echo an original). Impact on task utility `unknown`; hypothesised test: [dev test plans](issue-43-68-synthetic-dev-test-plans-v0.1.md) fidelity cases with and without full source context, graded on whole-task output.
6. **Operational complexity and cost.** Qualitative only: every adapter must implement one envelope construction/parse path and prove it at its own release boundary. Runtime, memory and staffing cost **UNMEASURED** — no adapter exists yet.
7. **Licensing/maintenance risk.** Internal module: no third-party licence, no external maintenance dependency. The identity provider (SSO/OIDC for humans, workload identity/mTLS/SPIFFE-like for services) is **unselected**; that selection is an open #46/#47 procurement question with no evidence here.
8. **Portability/replaceability.** The normalized, bound envelope/serializer contract plus its versioned proof fields; adapters translate native protocol → envelope and must use the bound serializer rather than forwarding raw wire (documented duplicate-key residual).
9. **Simpler alternative.** *Trust the harness/adapter* (the common proxy pattern) or *let a proxy guardrail own the check* (e.g. a configured Presidio guardrail, L1/L2). **Rejected:** security-model invariants 6–7 and the documented fabricatable-context finding; a proxy configuration is not an authenticated binding.

Gate: the existing normalisation property tests plus the adversarial nested/encoded fixtures; any newly found miss becomes a sanitised regression (never a policy change).

6. **Operational complexity and cost.** Pure, provider-independent functions; qualitative complexity is low and already merged. **UNMEASURED** at runtime under load.
7. **Licensing/maintenance risk.** Internal: no third-party licence.
8. **Portability/replaceability.** Pure functions over canonical views; no provider dependency, so replacement is local.
9. **Simpler alternative.** *Let the model or harness normalise.* **Rejected:** the model is untrusted for policy context (invariant 6), and a value lost before candidate generation cannot be recovered later ([architecture.md](../architecture.md#detection-pipeline)).

### 4. Deterministic secret and infrastructure detection (#8, #9)

**Proposed choice: build Hylja-specific deterministic authority; keep the reuse of *generic syntactic recognizers* as candidate sources explicitly open for #40/#46 evaluation.** Proposal only.

1. **Evidence source and tested version.** Requirements: [security-model.md](../security-model.md#security-invariants) invariants 1 and 8, [architecture.md](../architecture.md#detection-pipeline) step 3, frozen [#8](https://github.com/Marcus-Levin/hylja/issues/8)/[#9](https://github.com/Marcus-Levin/hylja/issues/9)/[#37](https://github.com/Marcus-Levin/hylja/issues/37). Implementation evidence: `#37`-adjacent NAME/EMAIL/PHONE candidate generation and `#8`-class deterministic detectors exist in this repository as **non-enforcing** modules with synthetic tests, and their bounded scope is in [docs/capabilities.md](../capabilities.md); the dated record of that scope is the retired plan's [frozen snapshot](https://github.com/Marcus-Levin/hylja/blob/f838fc2dc8da0402338d4dfd1c028392a9f4b9ee/docs/plan.md#current-state). Candidate evidence at pins: **P7** (`IpRecognizer` declares `supported_entity="IP_ADDRESS"` with IPv4/IPv6/embedded/mapped regex patterns at fixed pattern confidences, English-only context words, and an `invalidate_result` that only rejects strings `ipaddress.ip_interface` cannot parse — **no** documentation-range, private/public or infrastructure-role logic), **P8** (`MacAddressRecognizer` → `MAC_ADDRESS`; `UrlRecognizer` → `URL` with standard/schemeless/quoted patterns; scores are pattern constants, optionally overwritten to MIN/MAX by validate/invalidate hooks or nudged by nearby context words), **P10** (`RecognizerResult.recognition_metadata` carries only recognizer name, recognizer identifier and a context-enhancement flag), **P1** (74 default registrations including credit-card, crypto, IBAN, phone, email, date, IP, MAC, URL), **P4** (`AnalyzerEngine` defaults `default_score_threshold` to 0, i.e. the caller owns acceptance), **O1**/**O5** (OPF's `v2` has generic `private_address`/`private_url`, `v4`/`v7` drop `private_address` for location labels, and no version has a host/DNS/engineering class; label meaning is training-fixed). **Tested:** repository synthetic suites; **candidates UNEXECUTED — no recall or precision figure exists for either**.
2. **Requirements met / not met.** *At source/document scope:* met by inspection — Presidio supplies **overlapping syntactic recognition** for address-shaped, MAC-shaped, URL-shaped and several credential-shaped formats; OPF supplies single-pass span labelling with a generic address/URL class. *Not met at source scope:* Hylja's requirements that these detections carry **semantic role, privacy/regulatory attribute, sensitivity and trust evidence, bounded provenance (source, sink, tenant, purpose), source-to-sink authority, and configured engineering identifier classes** (customer/project/asset/ticket/system identifiers) — none of which appears in P7/P8/P10 or O1/O5; the `#8` zero-plaintext criterion and blocked-secret irreversibility are Hylja's own; and **no documentation-range or role distinction** exists in the pinned IP recognizer, so documentation IPs and internal hosts are treated alike. *Unproven at runtime:* recall, precision, false-cloak and critical-miss rates for both arms on engineering-heavy text.
3. **Critical counterexample / test gate.** Two paired synthetic cases: (a) a config/log line where `192.0.2.10` in a firewall rule **must survive** for the task to be correct — an `IP_ADDRESS` hit here is a false cloak; (b) an internal FQDN under a reserved synthetic suffix such as `db-customer-a.example.invalid`, which the pinned `UrlRecognizer` **cannot** match because its suffix list is a fixed enumeration that excludes `.invalid` (**P8**), so a Presidio arm run on `.invalid`-only fixtures would return zero URL hits and could be read as detector quality; the paired `db-customer-a.example.com` shape does match, which is why both sides of the pair are required. Gate: #40 per-class and per-content-family recall/precision with **paired suffixes**, documentation-range negatives, each critical miss listed individually, and **no** semantic judge or sentinel catch counted as detector recall.
4. **Privacy/security residual risk.** Registration is not efficacy: a pattern confidence with a caller-owned threshold (**P4**, **P8**) can be tuned either way by an integrator; regex timeout handling skips a pattern and logs; validate/invalidate collapse scores to MIN/MAX, discarding nuance; a regex recognizer cannot know whether the string is an example, a customer asset or a secret.
5. **Utility/fidelity impact.** Directly coupled: over-cloaking an address that carries task meaning can silently change an engineering answer. `unknown`; hypothesised test: whole-task grading of a log diagnosis, a config edit and a script edit with planted infrastructure identifiers, per the [fidelity plan](issue-43-68-synthetic-dev-test-plans-v0.1.md).
6. **Operational complexity and cost.** Presidio adds a spaCy dependency and a **separately selected, separately sourced** language model (**P3**); OPF adds model weights fetched **without a revision pin** on first run (**O2**), which is exactly the air-gap hazard #33/#35 must pin. Packaging, CPU/memory/GPU burden and latency: **UNMEASURED**, and no arm has been run.
7. **Licensing/maintenance risk.** MIT (Presidio, per register) and Apache-2.0 (OPF code and weight card, per register); both wheels/weights still require the [Presidio artifact dossier](https://github.com/Marcus-Levin/hylja/blob/main/docs/research/issue-46-presidio-artifact-prescreen-2026-10-01.md) checks (`has_sig: false`, no LICENSE file inside either wheel, Fulcio certificates whose source/build/run claims are **unverified rather than absent**) before any execution. Maintenance and transitive/SBOM state **unknown**; `litellm` already moved two patch releases past the inspected pin (**L5**), so pins decay.
8. **Portability/replaceability.** A narrow candidate-source contract (span + recognizer identity + version) lets a Presidio recognizer, an OPF span and a Hylja rule be interchangeable at the input of #3. The *authority* stays Hylja's, so swapping a syntax recognizer cannot silently change a policy outcome.
9. **Simpler alternative.** *Adopt the Presidio default recognizer set as the detector layer.* **Rejected for authority** (no role/provenance/authority; caller-owned thresholds; default threshold 0; no documentation-range logic), while **reuse of individual generic recognizers as candidate generators remains undecided** and is routed to #40 plus the #46 artifact screen. This is the correction made after an earlier draft described overlapping recognizer work as un-substitutable absence: the honest statement is *partial syntactic overlap, unmeasured efficacy, no Hylja authority*.

## 2. Trace of the required flow (unchanged, restated for completeness)

Authenticated caller/tenant/purpose/source **and actual routed sink/profile** ([#2](https://github.com/Marcus-Levin/hylja/issues/2)) → classification with provenance and sensitivity/trust evidence ([#3](https://github.com/Marcus-Levin/hylja/issues/3)) → deterministic source-to-sink decision ([#4](https://github.com/Marcus-Levin/hylja/issues/4)) → conditional brokered USE/DISPLAY/EXPORT when an original is needed ([#17](https://github.com/Marcus-Levin/hylja/issues/17)) → independent inspection of the **exact post-serialization outbound bytes** at the sink ([#19](https://github.com/Marcus-Levin/hylja/issues/19)). Missing or forged context, UNKNOWN/conflicting classification, outage or unchecked mutation never authorises release. [#28](https://github.com/Marcus-Levin/hylja/issues/28) administers version; [#4](https://github.com/Marcus-Levin/hylja/issues/4) owns effect; only [#32](https://github.com/Marcus-Levin/hylja/issues/32)'s deployed/attested network controls support a complete managed-egress claim.
