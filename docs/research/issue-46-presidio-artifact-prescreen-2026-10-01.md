## License and provenance observations

Both actual wheel `METADATA` files declare `License-Expression: MIT`. The [source LICENSE at the inspected release commit](https://github.com/data-privacy-stack/presidio/blob/779dbd286d5ef4d1fbe2514275fb1bce358f2417/LICENSE) contains the MIT permission grant and notice condition, and it is byte-identical (`sha256 f3e86ee59a49bcfb0d9a9547484d55224ea7b2d04f95b1947b4d18d17f6de535`) at the certificate-claimed build commit named below. However, each wheel's `.dist-info` inventory is only `METADATA`, `WHEEL` and `RECORD`: neither contains a LICENSE/NOTICE file. Source and package declarations agree, but the redistribution-notice gap needs resolution before packaging or adoption. The declaration alone does not prove which source tree produced a wheel.

PyPI publishes [analyzer](https://pypi.org/integrity/presidio-analyzer/2.2.364/presidio_analyzer-2.2.364-py3-none-any.whl/provenance) and [anonymizer](https://pypi.org/integrity/presidio-anonymizer/2.2.364/presidio_anonymizer-2.2.364-py3-none-any.whl/provenance) attestation bundles. Their publisher metadata names GitHub repository `data-privacy-stack/presidio` and workflow `release.yml` and leaves `environment` empty. The decoded in-toto statements carry PyPI's publish predicate type and a null `predicate`, which that [predicate type](https://docs.pypi.org/attestations/publish/v1/) requires: it conveys the Trusted Publisher through the signing identity rather than a statement body. The subjects name the exact filenames and SHA-256 values above.

**Certificate contents were parsed as data, not verified.** Each bundle embeds a short-lived Fulcio leaf certificate (`O=sigstore.dev, CN=sigstore-intermediate`, ten-minute validity around 2026-07-22T07:54:26Z/07:54:28Z, code-signing EKU, an embedded precertificate SCT). Read against [Fulcio's OID directory](https://github.com/sigstore/fulcio/blob/main/docs/oid-info.md), both certificates assert the same values: build signer URI `…/.github/workflows/release.yml@refs/heads/main`, source repository digest `636cadd91675c61c71923d8d68eaa9511073826a`, source repository ref `refs/heads/main`, build trigger `workflow_dispatch`, run invocation URI `…/actions/runs/29901897108/attempts/1`, runner environment `github-hosted` and repository visibility `public`. The two certificates are distinct (different serial, key and validity seconds) with identical extension values. **No signature, certificate chain, embedded SCT or transparency inclusion was cryptographically verified.** These are therefore unverified claims about how the files were published, and artifact provenance stays unauthenticated until they are.

**What public sources do establish, separately from the certificate claims.** GitHub reports tag commit `779dbd2` as having the single parent `636cadd`, so the commit the certificate claims as the build's source is the tag commit's **parent**, not the tag commit. That compare is one commit ahead and changes only `presidio-structured/pyproject.toml` and `presidio-structured/uv.lock`, neither of which either wheel packages: the two `RECORD`s list only `presidio_analyzer/` or `presidio_anonymizer/` plus `dist-info`. Run [29901897108](https://github.com/data-privacy-stack/presidio/actions/runs/29901897108) publicly reports workflow `Release`, event `workflow_dispatch`, `head_sha 636cadd91675c61c71923d8d68eaa9511073826a`, path `.github/workflows/release.yml`, attempt 1, created 07:53:51Z, conclusion success, and that workflow file exists at `636cadd`. The chronology fits that story: build commit 07:43:33Z, run created 07:53:51Z, uploads 07:54:34Z, tag commit 08:17:15Z, release published 08:30:12Z. So `779dbd2` did not exist when the wheels were uploaded, and the only difference between the claimed build commit and the release tag commit is a `presidio-structured` dependency-floor change that neither wheel ships. All of that is a **digest comparison plus public-record comparison**. It is not signature verification, not an authenticated-publisher conclusion and not reproducible-build evidence; it cannot be cited as a provenance pass until the published attestations are verified.
