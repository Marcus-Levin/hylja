## Problem and concrete trace

The [decision 013](013-local-listener-caller-gate.md) bearer grants local access, not a principal or tenant identity. In the #261 seam, eight sender/receiver identity/request/source/route windows are pinned once. At their earliest expiry a second valid bearer request refuses; constructing a fresh conversation owner preserves the same stale evidence. Replacing their timestamps with `now` would turn host fixtures into counterfeit request evidence. A tenant header or a new owner is equally insufficient.

The required chain is instead: independently enrolled workload -> verified possession on an actual connection -> independently provisioned subject/context and current grants -> bounded canonical request on that connection -> observed source and controlled actual sinks -> real classification/policy -> exact-byte sentinel -> final live guards -> effect. Authentication establishes who connected; it does not select KEEP/MASK or authorize SEND.

| Approach | Possession/principal basis | Cost and remaining counterexample | Disposition |
|---|---|---|---|
| Workload mTLS | Native validated client-certificate handshake; independent enrollment maps verified certificate to canonical workload | CA/key custody, renewal and live revocation are still needed; a valid CA-signed but unenrolled certificate must deny | Recommend native mTLS for the first local synthetic connection proof, with exact certificate enrollment, not a SPIFFE implementation claim |

Standard-design references, not independently tested candidates: [SPIFFE X509-SVID](https://github.com/spiffe/spiffe/blob/main/standards/X509-SVID.md), [JWT validation BCP RFC 8725](https://www.rfc-editor.org/rfc/rfc8725), [DPoP RFC 9449](https://www.rfc-editor.org/rfc/rfc9449) and [TLS 1.3 RFC 8446](https://www.rfc-editor.org/rfc/rfc8446). The SPIFFE/JWT references are comparison pointers, not source-inspected implementations or adoption evidence. This does not decide broad reuse/buy/build [#48](https://github.com/Marcus-Levin/hylja/issues/48) or repeat #65/#66 research.

Exact certificate enrollment avoids a new SAN parser and any CN/SAN/header-to-tenant shortcut. It is intentionally less operationally convenient than a deployed workload identity service. Rotation requires a new authorized enrollment; a copied public certificate without its private key cannot complete the possession proof. A stolen private key can impersonate its workload until revocation: no host-compromise defense is claimed.

## Proposed issuer, enrollment and authority model

The first proof trusts one **test-local synthetic enrollment CA**, administered by the test/control-plane operator, not the gateway client. The enrollment operator supplies a reviewed trust anchor and server certificate, issues distinct synthetic client credentials after assigning workload identity, and independently provisions a bounded registry keyed by SHA-256 of the exact verified leaf DER. That registry maps to canonical `principalId`/`workloadId`; certificate names, token shape and payload metadata are never the mapping authority. Production issuer/enrollment provider is deliberately unselected.

CA private material stays outside the gateway data plane; client private keys stay with their workload. Default future tests to ephemeral in-memory key generation, with no private-key material tracked. The current fixture guard rejects tracked key-container extensions everywhere and private-key PEM markers in fixtures, including synthetic-golden; its synthetic-assignment exemption does not admit private keys. Any tracked private-key proposal requires a separate reviewed guard-policy decision outside this task. Re-encoding, renaming, private-JWK fields or another representation to evade detection is forbidden. Node key generation does not issue X509 certificates: synthetic issuance/provisioning and custody remain unresolved admission prerequisites. No real key, certificate subject, production mapping or private traffic is admitted. Do not log public credential fingerprints as anonymized user data. Production renewal, custody, attestation and compromise response need another decision.

A current independent authority record, indexed by enrolled identity, pins exactly one tenant/project membership, server-assigned session, permitted purpose, policy id/version/content digest, upstream numeric loopback tuple, and distinct upstream/client destination profiles. There is no wildcard, client selector or arbitrary URL. Session and purpose are assigned by the control plane; any supplied override refuses. Enrollment, membership and effect grants are separate records even if the synthetic fixture operator provisions them together. A valid enrolled workload without a current matching grant gets no effect.

Revocation source: the operator-owned, monotonically revisioned in-process enrollment/grant registry with an explicit availability lease. Removal, revocation, revision mismatch, lease expiry or inability to obtain a coherent current view denies. Native certificate validity is also checked; successful handshake is never an indefinite lease. Initial proof leases are capped at five minutes and never extend credential, grant or authority expiry. A new observation may produce a new request's evidence only while all independent origins remain live; an in-flight interaction is never renewed or re-enveloped to preserve a stale decision. Cross-process revocation consistency remains outside this synthetic proof.

Only a native `secureConnection` socket that is authorized against the pinned CA, has a bounded usable certificate matching a live exact enrollment, and has negotiated the admitted TLS profile establishes possession and principal. Assign a private connection identity to that socket. Do not accept callers' socket-shaped objects as authentication; the authenticator owns server creation/event enrollment and its private handle registry. Disable renegotiation, reject resumed sessions for the first proof, and admit no early application data. Exact resumption/early-data refusal mechanics and certificate extraction/validity API shapes must be verified against the pinned Node runtime before implementation admission closes.

## Evidence inventory and lifecycle

Proof references name provider-owned records, not bearer approvals. All records bind connection identity, one server-generated request id, direction, canonical request digest, authority revisions and scope. The response record additionally binds request id and canonical response digest. Digests remain private ephemeral bindings, never diagnostics or clearance. Four proofs per direction stay in envelope order; the provider retains their richer origin records privately.

| Proof | Origin and binding | Scope/freshness | Last revalidation owner |
|---|---|---|---|
| Sender identity | Authenticator's actual mTLS socket enrollment, verified certificate and canonical subject | Connection + subject; certificate validity, live enrollment revision and lease | Authenticator live check inside gateway's final dispatch guard |
| Sender request | Evidence provider observes completed strict request on that authenticated socket and assigns a once-only request id/digest | Subject + tenant/project/session/purpose + operation + control-plane grant revision; request observation time bounded by all origins | Provider, after readiness and every host observation, before upstream write |
| Sender source | Adapter records actual inbound socket and complete admitted request, source profile/trust from independent configuration | Same request/connection; source observation, connection liveness and configuration lease | Gateway/provider final dispatch guard; never derived from bearer alone |
| Sender route | Controlled transport's immutable target plus independent profile record at preparation; live reached tuple at readiness | Same request, approved numeric endpoint/profile and committed policy; route lease plus connected-socket tuple before bytes | Owned transport final write guard; planned route alone never suffices |
| Receiver identity | Same enrolled requesting workload and original client connection, not identity asserted by provider text | Original request's identity origins; no fresh identity from model output | Authenticator/gateway immediately before client write |
| Receiver request | Provider correlates one complete reply to the once-dispatched request and binds canonical response | Original scoped request + response digest; live grant, original request lease, new reply observation time | Provider/receiver before release, gateway after framing before write |
| Receiver source | Owned transport observes complete strict reply on the exact upstream socket used for dispatch | Actual upstream tuple + request correlation; always `UNTRUSTED`; observation capped by original authority | Transport/provider before receiver construction and release; retain settled observation when transport closes normally |
| Receiver route | Gateway's private response socket is the original authenticated client socket; independent client profile | Same connection/request, live socket, profile/control-plane lease, no sink replacement | Gateway immediately before captured client write |

A timestamp is only a cap on a real observation. It cannot create source trust, membership, policy commitment, actual route or reply correlation. Before upstream readiness the sender route record describes an approved **planned** endpoint; readiness must promote it with actual owned-socket observation under the same immutable record, or refuse. Boundary proof timestamps and references do not change. If this distinction cannot be represented safely, the shared-owner prerequisite must change the handoff, not label a planned connection as observed.

## Final effect continuity and exclusions

The separately admitted handoff must retain sender/receiver policy and exact-byte sentinel checks unchanged. After each awaited operation, perform all trusted callbacks first, then normalized evidence checks. At the actual write use only private owned state: same request/connection, current registry revisions/leases/certificate, committed policy/profile, actual tuple, sticky cancellation, unused effect flag, liveness and absolute deadline. Set the once-only flag and call the captured native write in the same synchronous continuation, with no host callback, property lookup, await, retargeting or reconnect between the last check and effect. Client framing needs a second private final check **after** encoding, not merely the receiver's pre-framing check. No original-specific refusal or raw native error reaches diagnostics.

Cancellation, incomplete HTTP, client close, shutdown and outages latch refusal, cancel both owners/children, destroy owned sockets and discard/wipe owned buffers. Expiry during finite observation or framing withholds the next effect; expiry after a native write began cannot unsend kernel bytes. Write timeout terminates further work and claims no rollback. A timer cannot preempt nonreturning trusted synchronous code. Shutdown must await enrolled exchanges and measure actual socket closure and worker absence, not infer either from an owner state. Unconfirmed worker cleanup stays restrictive.

Authentication proves neither classification nor policy clearance. Fixture-backed labels stay explicitly fixture-backed; generic inspection needs its separate unadopted human gate. No mapping lookup, resolution/restoration, streaming/tools/images, real provider/SDK conformity, utility, held-out scoring, managed-egress/bypass resistance or production-risk adoption is authorized. Broader tenant/reversible claims still require [#14](https://github.com/Marcus-Levin/hylja/issues/14), [#15](https://github.com/Marcus-Levin/hylja/issues/15), [#16](https://github.com/Marcus-Levin/hylja/issues/16) and [#17](https://github.com/Marcus-Levin/hylja/issues/17); this does not complete parent #21.

## Recorded human acceptance and scope

On 2026-10-06 the project owner replied "I accept" to the recommendation for these two bounded design choices:

1. **Synthetic native mTLS:** a real client certificate, independently enrolled exact certificate-to-workload mapping and live expiry/revocation checks. Production issuer, SPIFFE deployment and production identity adoption remain deferred.
2. **Staged evidence integration:** direction-specific observations, response-time receiver construction and final owned-write guards through separately admitted A/P/B/C units, not a monolithic rewrite.

This accepts those design choices only, not runtime implementation before its prerequisites or merging PR #264. Certificate issuance/provisioning and custody remain unresolved; an offline OpenSSL-based issuer was suggested, but no fixture mechanism, binary or dependency has been admitted or executed.

Rejected simpler alternatives: bearer -> principal, localhost -> tenant, CN/header/body -> scope, clock -> all proofs, new owner -> renewal, caller profile -> actual sink, unchanged shared `observe()` -> both routes, and detector absence -> clearance. Each omits an independent fact required at the effect.

Unresolved before runtime dispatch: reviewed synthetic certificate creation/custody without new unapproved dependencies or binaries; exact Node TLS/X509 typing, resumption/early-data handling and certificate-size bounds; the shared-owner API and coherent registry snapshot ownership; exact lease durations and shutdown failure handling. Resolve these in narrow admitted unit briefs, not by silently loosening this design. The recorded acceptance of choices 1 and 2 is distinct from the still-required independent exact-head review, explicit merge/release authorization, deployment/production privacy-risk acceptance, generic inspection approval, decision 010/taxonomy/information-model/transformation acceptance and frozen evaluation/custody/rubric gates. None of those remaining gates is satisfied by this acceptance record or its prose checks; broader #21 completion is not authorized.
