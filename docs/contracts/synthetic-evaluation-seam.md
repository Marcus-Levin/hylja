# Preparatory synthetic evaluation seam (#5)

This is **evaluation-only and NON-ENFORCING**. It is not a policy engine, an authentication boundary, a real vault/key/cache/broker isolation proof, a transport interceptor, or the independent final-byte #19 egress sentinel. No real/private data or external network traffic belongs in this seam. The authoritative evaluation rules remain in [evaluation.md](../evaluation.md); implementation status belongs only in [plan.md](../plan.md#current-state). The public #39 p0.1 proposal is context, **not** a frozen v0 protocol or a scored result.

## Registration and candidate handoff

`createDevelopmentEvaluation()` registers a bounded development case first, an independently authored planted oracle second, then candidate events or one `runCandidate(caseId, callback, capture)` invocation. The versioned case has a development family ID, fields of synthetic source text, observed sink IDs/surfaces/profile IDs, optional synthetic tenant/project/session/principal/purpose/provenance *fixture labels*, and an optional task prompt. Those labels are test data, **not** authenticated credentials or actual route/profile binding. The oracle must be authored/reviewed independently of candidate spans, classifier output, sentinel catches and downstream answers; its UTF-8 occurrence offsets are verified against planted case bytes at registration. It specifies semantic type/subtype, sensitivity, trust, expected per-sink treatments and optional independent task answer. Treatment metadata is *oracle expectation only* and does not invoke or simulate #4 policy. For this preparatory SECRET check, every captured sink is an explicitly disallowed plaintext sink; `CREDENTIAL_OR_SECRET` must be labeled `SECRET` even in the independent oracle, and both it and any other `SECRET` reject `KEEP` rather than quietly treating it as an allowed policy exception. Contradictory credential sensitivity is rejected at registration, with the metric also selecting by credential semantic type as defense in depth.

The `DevelopmentCandidate` callback receives a frozen copied **candidate-facing view only**: case ID/family, synthetic fields, fixture context, sink IDs/profiles and task prompt. It never receives the planted oracle, expected task result, report, grader or raw sink captures. It returns bounded field/byte-span events and optionally a task response. The second callback argument accepts only an already-serialized `{ body: Uint8Array, metadata: Uint8Array }` for a declared controlled sink. An evaluator-owned `createInMemorySinkCapture()` snapshots those exact supplied bytes, including serialized metadata/headers; it never sends data. A real future adapter must actually connect its last serialization step to a controlled sink—self-reported candidate strings, a reconstructed JSON object, or an omitted send are **not** evidence of interception. Every expected sink with no captured bytes remains `untested`. The evaluator separately invokes `report(caseId, capture, taskGrader)` and may record evaluator-origin latency (ms), compute time (ms), and synthetic model/API cost (microunits); no candidate can self-grade through its result. Dispose of both in-memory registries/captures after a run; do not persist raw captures.

Bounds: 256 cases per registry, 32 fields / 8 sinks / 256 independent occurrences / 256 candidate events per case, 64 KiB combined case field bytes, 64 captured releases of at most 1 MiB each and 8 MiB total in a capture. Ordinary reports use evaluator-minted, per-registry ordinal `case-N` and per-case `sink-N` references rather than caller-authored case/sink IDs; even a protected **prefix** inside a fixture ID cannot enter those report fields. Keep the raw-to-report association only in disposable evaluator memory. Payloads, oracle strings, task prompt/answer/response, arbitrary metadata, exceptions and raw capture bytes are excluded from reports and error messages. The scalar report separates `observed` rows (`independently-executed` provenance and an outcome) from `untested` rows (no outcome), and keeps independent counters for exact SECRET plaintext escape, pre-policy candidate matching and downstream task correctness. Candidate recall/precision use one-to-one exact field/byte/class/subtype matches; zero denominators are `null`, never 100%. SECRET containment is checked against the independent oracle's UTF-8 bytes in both captured body and metadata, **not** against candidate labels; critical escapes count planted occurrences per tested sink, not repeated fragments. A correct task answer cannot offset an escape. A no-capture sink cannot become a zero-leak pass. No post-capture mutation, arbitrary representations/encodings, contextual inference, stream holdback, opaque surfaces or network bypass are asserted by this development metric.

Public family IDs `D01`–`D12` and blind family IDs `H01`–`H04` live in [evaluation-partitions.ts](../../src/evaluation-partitions.ts); the registry only accepts development cases. **No** blind fixture payload, oracle label/answer, seed, capture or scoring artifact belongs in this repository or candidate-facing callbacks. Family IDs alone do not prove structural independence of later blind *content*. Separate evaluators must review independent narratives/workflows, pre-tuning treatments and task expectations, access controls and manifest integrity before freezing a #39 comparative protocol; this seam does not freeze or score v0.

## Runnable synthetic scope/authorization contract

`runSyntheticScopeContract(boundary, references?)` calls an injected `SyntheticScopeBoundary` with `canResolve` and `authorize`, both boolean/async boolean. It supplies synthetic A/B references for **candidate, entity, token, ciphertext, cache and synthetic-identity** kinds with tenant, project, session, principal, purpose, destination and provenance fixture labels. It checks both allowed same-scope USE and denied wrong-tenant/project/session/provenance/principal/purpose/destination, unknown references, cross-tenant exception claims and USE/DISPLAY/EXPORT separation. `generateSyntheticScopeVectors` adds reproducible bounded seeded negative mutations. The optional caller-supplied fixture array is snapshotted from at most 32 own data descriptors before generating cases; changing Proxy lengths, accessor elements and overridden array methods are rejected or bounded without visiting unbounded indices. Boundary methods are snapshotted once under a non-echoing error boundary; throwing getters/Proxy traps cannot expose planted error text. Throwing/non-boolean implementations fail rather than counting as denials; sanitized finding IDs carry no reference/plaintext values. The suite must pass a minimal scoped synthetic double **and fail** an intentionally permissive always-true double. Supplying scope labels to a test double does **not** authenticate a runtime caller; later storage, key binding, broker and cache integrations must rerun the contract at their actual boundaries. It exposes no plaintext mapping lookup API.

## Reviewed #4 pure-policy integration (still evaluation-only)

`makeSyntheticPolicyFixture(tenant, kind, candidateRef?)` authors only synthetic A/B contexts and separately pinned #3 composed-classification and #4 bundle digests **before** the mutable request is constructed. The fixture helper, pin, subject, route and reviewer object are local test inputs, not authenticated principals, a trusted production policy distribution, or a real approval. `runSyntheticPolicyInvariants(adapter?)` injects the real `decidePolicy`/`decideReviewedPolicy` implementation by default and checks fixed expected SELECTED/HELD/DENIED states/treatments against public positive and negative controls: source-to-sink rules, absent profile, mismatched route/tenant/project/session/purpose/candidate, replaced bundle or composed classification, semantic `KEEP` against BLOCK, unresolved parser evidence, and independently reviewed candidate/tenant-bound approvals. It also runs against an intentionally permissive always-KEEP test double that must fail many cases. Findings contain only fixed test IDs, expected state and pass/fail, never raw policy input, review details or model traffic. A throwing adapter cannot make a denial pass or leak its error text into findings. This exercises the real **pure decision seam**, not #4's deployment/authentication obligations. A selected local USE decision is deliberately paired with a separately injected synthetic A/B resolution/authorization double: DISPLAY, EXPORT and cross-tenant USE still deny. Policy selection does not authorize a mapping, broker operation, review approval or byte release; the adapter owns no vault or transport, and this test never sends external data or claims actual sink interception.
