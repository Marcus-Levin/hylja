# Bound runtime USE executor

Status: contract for [`src/mapping-use.ts`](../../src/mapping-use.ts) ([#211](https://github.com/Marcus-Levin/hylja/issues/211)). It defines one runtime executor for `USE` on **exactly one** opaque mapping reference. The other seams named here own their own contracts and are not restated: [mapping-authorization.md](mapping-authorization.md), [policy-contract.md](policy-contract.md), [audit-ledger-contract.md](audit-ledger-contract.md), [mapping-metadata-registry.md](mapping-metadata-registry.md), [mapping-aead.md](mapping-aead.md), [mapping-lifecycle.md](mapping-lifecycle.md). Implementation status lives only in [capabilities.md](../capabilities.md); [`test/mapping-use.e2e.test.mjs`](../../test/mapping-use.e2e.test.mjs) is the authoritative record of every assertion.

## The one operation this executor has

`createBoundMappingUse(trustedHost)` binds one reference, one tenant/project/session scope, one entity, the current-record registry, the audit substrate, the pinned policy handoff and one **private synchronous resource** at construction, and returns `{ use(): Promise<{ version: 1, code }> }`. That object is the whole interface.

- `use()` takes **no argument**. The caller supplies no operation, no reference, no authority, no grant, no key, no callback and no effect.
- The result is one fixed code out of `USED`, `NOT_FOUND`, `WITHHELD`, `FAILED` and nothing else. There is no reason, no reference, no identifier, no byte count and no exception. An unusable host is refused at construction with one fixed `TypeError` carrying no supplied value.
- There is no reference argument, no enumeration, no scan and no bulk path, so this is not a mapping lookup API ([decision 004](../decisions/004-brokered-vault-no-direct-mapping-api.md)). The original value is never returned to any caller; it is spent on one local synchronous resource that already knows its own record's identifier.
- `USE` never implies `DISPLAY` or `EXPORT`. Those are separate grants on a separate seam and have no path here.
- A second `use()` that overlaps an unfinished one is refused immediately, before any host call, because an overlapping effect on one reference has no coherent snapshot to spend. A sequential second use is a fresh observation, not a cached one.

## Bound at construction, never frozen as authority

Bound: the reference, the scope, the entity, the registry object and its `current`, the audit ledger and its trusted context, the pinned classification, bundle and digests, the backend object **with the `lookup` method read from it once, here**, and the `authority` and `material` callables. The `lookup` binding is fixed for the life of the executor: a method installed on the backend object after this point is never invoked, so no replacement can be reached on the recovered bytes at any later point of a call either.

**The backend's nonretention obligation is mandatory.** `MappingUseBackend.lookup` must decide and return one primitive boolean, and nothing else. It must **not retain, copy, log or forward** the bytes it is handed: no reference kept to that buffer, no copy of its contents stored anywhere, no bytes in a log, a metric, a trace or an error message, and no forwarding to another party, process or transport. The recovered plaintext exists for the duration of one `use()`; the executor overwrites its own copy in the same continuation, in a `finally`, whichever boolean comes back, and a copy the backend kept outlives that.

This is an **obligation on the host, not a guarantee from this module and not a zeroization claim**. Nothing here observes what the backend did with the buffer after it returned, nothing reaches a retained copy, and nothing forces native memory, garbage-collected buffers or swapped pages to be zeroed. The executor can prove only its own half: the plaintext it created is overwritten in that `finally`. The backend's half is stated here as a duty and, in [Limits](#limits), as an unproven one.

**Not** bound: the authenticated subject and context, the observed route, the explicit grant, the current key version and the clock. Those are a host obligation, read again at the start of every `use()` and again after every external callback. A grant revoked, a route changed or a key rotated between two observations is observed, not spent.

`authority` and `material` may answer with a value or with a promise. Every answer is awaited inside the call that asked for it, before anything reads it, so no promise outlives its `use()` and no observation is read half-settled.

## The order inside one `use()`

1. **Bind** every callback function **and its receiver** once, at construction: the host's own `authority` and `material`, and the backend object with its `lookup` method. A method re-pointed, swapped or re-targeted after construction cannot change what runs, and a host callback method runs with the host as its receiver, as its own `this`. No callback function is looked up again inside a `use()`.
2. **Observe** one coherent current authority; require the bound scope, so a foreign scope never reaches the registry, the grant, the policy or the resource.
3. **Bind the owned audit identity**: require the audit substrate's recorded actor to be this authenticated subject, and read the trusted context's actor once into a frozen snapshot congruent with it. The ledger takes the actor from its trusted context and never from a draft, and it is handed *that snapshot*, not the host's live actor. Require the substrate to be **this bound scope's own stream**: the ledger's own scope and the trusted context's scope must both be the bound tenant/project, because the ledger pseudonymizes every reference under that scope's own key. This congruence is required before any effect exists and again immediately before every append.
4. **Select** with the real `decidePolicy` for `USE` over the independently pinned classification digest and bundle digest; require `SELECTED` and `KEEP`.
5. **Read** the real registry `current`; require `FOUND` and `ACTIVE`. The record is read whole and matched to the bound reference and the bound scope **before** its lifecycle state is allowed to mean anything: a malformed, unreadable or foreign record is refused with no evidence.
6. **Authorize** with the real `authorizeMappingOperation` for `USE`; require `AUTHORIZED`. An authority answer that carries no grant at all reaches this step as the seam's own absent grant rather than as a boundary refusal, so that denial is the seam's to name; a grant that is present but structurally invalid is still a boundary refusal with no evidence.
7. **Load** the sealed record and the DEK into owned copies. These awaits - and the awaited authority answers - are the only suspension points, and no plaintext exists while they run.
8. **Recheck after every external callback** - the material load and each audit append: observe again, require a clock that has not moved backwards, require the actor, context and route to be unchanged, require the live audit actor to still be the captured one, rerun the real policy over the pinned bundle and require the same decision reference, re-read the real registry, reauthorize on the claim that read reduced to owned values, and require an unchanged revision and an unchanged key version with material that is still the material this instant would use. The order inside one recheck is deliberate: the live audit actor and the pinned bundle are host-owned objects and are read first, the real registry read follows, and everything after it reads only values this module already owns.
9. **Record** the authorization attempt and the policy decision with the real `appendAuditEvent`, re-requiring the stream congruence above immediately before each one, gating each on `gateHighRiskEffect` applied to the value `appendAuditEvent` itself returned - never a fabricated `RECORDED` result - and recheck again.
10. **Sealed effect**: the last answer this call awaits is one more authority observation. From the continuation that reads it, the whole final guard and the effect run **in that same continuation**: no `await` at all sits between them, so a revocation queued by any host callback, a late host property read or a dynamic function lookup cannot land between the fresh registry read and the opener or the backend. The AAD carries the classification primitive captured before the last guard, never a property read from the host's classification object; a captured opener and one captured `Reflect.apply` invoke the real `openMappingPayload` on an independently established expected scope, and the `lookup` binding captured at construction invokes the real synchronous backend on the backend object bound at construction to decide on the recovered bytes. The final guard is normalized whole, so a fault raised by a host value inside this segment - including a trap raised while the live audit actor is being re-read and reflected on - is still a guard refusal and not a reached effect; only the opener and the backend are left unnormalized.
11. **Clean up**: every owned byte buffer - each envelope copy, the DEK copy and the recovered plaintext - is enrolled the moment it comes into existence, so a copy interrupted part-way through by a throwing byte read is overwritten like any other, and all of them are overwritten in one `finally`, on the success path and on every exceptional path, in the same continuation that spent or refused the effect.

The order of steps 3 to 6 is deliberate, and it is the same rule step 8 repeats at every recheck: the authority answer, the live audit actor, the pinned bundle and the registry are the four host-owned reads of that pass, so each happens as early as its own guard needs it and the fresh registry read is the **last** host-owned read of the call. Every step after it - the authorization, the material congruence, the effect scope - works on values this module already owns. Nothing about that order weakens a guard: each step is a complete guard on its own, and a refusal at any of them withholds.

## The fixed codes

| Code | Exactly when |
|---|---|
| `USED` | the captured backend returned the primitive boolean `true` |
| `NOT_FOUND` | the captured backend returned the primitive boolean `false` |
| `WITHHELD` | any guard refused: an unreadable or foreign scope, an absent or non-`ACTIVE` record, a registry record that cannot be read as this bound reference's own record in the bound scope, a denied authorization, a `BLOCK` or `HELD` policy decision, a stale revision, a rotated key, a moved or expired instant, an absent or incongruent audit record, an audit substrate that is not this bound scope's own stream, a changed actor or route, an opaque or throwing host callback, a reflection, enumeration or index fault raised by a host value - before the effect segment or inside it, before the opener is invoked - an overlapping call, an opener refusal, or a backend answer that is not a primitive boolean |
| `FAILED` | the sealed effect segment reached the effect itself and could not complete it: the opener or the captured backend threw, whether from its body or from its own invocation |

Nothing else maps to a `USE`. A backend that answers with anything but a primitive boolean withholds; its exception text never reaches the caller.

## Refusal evidence

Two refusal classes, and only those two, leave a record, through the same real `appendAuditEvent` and the same owned actor, frozen context and pinned bundle identity the accepted path uses, as one `AUTHORIZATION_ATTEMPT` / `USE` / `DENIED` event:

| Refusal | Recorded reason | Named by |
|---|---|---|
| the bound record is no longer live, or no longer `ACTIVE` | `LIFECYCLE_DENIED` | the real registry's own `NOT_LIVE` answer, and a record already matched to the bound reference and the bound scope, read rather than inferred |
| the authorization seam finds no grant at all, or a grant that has already expired | `RESOLUTION_DENIED` | the real authorization decision's own `NO_GRANT` / `GRANT_EXPIRED` reason |

Both guards run before the material load, so a record costs **zero** material callbacks, zero opener effects and zero backend calls; the sealed bytes never exist on that path. Both are recorded at the stage where the call has already established the bound scope, the authenticated subject, an audit identity congruent with it and an audit substrate that is this bound scope's own stream, and the record is written between the guard that refused and the refusal that is rethrown - so a run either records the refusal or withholds, never both. That stream congruence binds the substrate by the tenant/project it **declares**: the ledger object, its keys and its durability are still the host's, and a stream that names a different project - or no project where this scope has one - is not congruent with this call.

**Everything else records nothing.** An unreadable or malformed authority, a foreign scope, a policy `BLOCK` or `HELD`, a grant that is misbound rather than absent or expired (another operation, revision, principal, destination or purpose), an audit actor that is not the authenticated subject, an audit substrate outside the bound scope's own stream, a registry record that cannot be read as this bound reference's own record in the bound scope - `null`, an empty object, a record with no readable scope, a record whose state is not a lifecycle state, or a record belonging to another scope - a host fault, and every refusal raised after the material load are unchanged `WITHHELD` results with an untouched ledger. Those refusals are not guessed at: there is no catch-all logger, no inferred identity and no reconstructed draft, so a malformed, foreign or trapping value can never be filed as evidence about somebody. The recorded class comes from the refusal's own fixed code and from nothing else, which is why a `DENIED` entry never names a lifecycle value, a grant value, a reference or an exception the executor did not read from a real seam itself.

A record never changes a code. The call is already `WITHHELD`, no effect depends on the record, and the appended result is deliberately not read and not passed to `gateHighRiskEffect` - there is no effect here to gate. A ledger that cannot commit therefore leaves the same `WITHHELD`, no exception and no effect: an audit outage on this path is not visible in the returned code, which is a limit, not a guarantee.

## Limits

- **The host is trusted, not authenticated.** This module verifies no principal, no workload, no token, no issuer, no key and no grant. A coherent but dishonest host is answered coherently and dishonestly. A host that lies *about* identity is not caught; a host that changes the world between two observations is.
- **Snapshots stop mutation, not a malicious host.** The construction-time bindings - including the captured callback functions, the captured receivers and the captured `backend.lookup` - the captured classification primitives, the owned audit identity, the normalized grant and the registry claim are this module's own immutable values, so re-pointing a method, swapping the actor object or editing the classification after capture cannot change what this one call does. That is protection against a host mutating its own configuration mid-flight; it is **not** a sandbox. A callback that is itself adversarial - one that lies in every answer, mutates the world from inside a synchronous call, or runs arbitrary code in this process - is still trusted, and the finite set of observation points below is all this module has.
- **The sealed segment is a scheduling fact, not a lock.** The final guard and the effect share one continuation, so nothing *queued* can slip between them. What a hostile host runs **inside** the sealed continuation - re-entrant code on a synchronous callback the executor itself invokes - is still trusted code, and the module's answer to that is the read order: every remaining host-owned read happens before the last one, which is the real registry read. Host honesty, cross-executor coherence and cross-process coherence remain host obligations.
- **Snapshot coherence is an obligation, not a proof.** The registry's own compare-and-set and single-event-loop atomicity are its contract's; this executor adds re-observation, nothing stronger. Two `use()` calls on two executors over one reference in one process can still interleave.
- **Key custody is the host's.** The DEK is supplied, copied once, used once and overwritten here. Generation, wrapping, rotation, storage, escrow and destruction are key-management obligations this module neither performs nor claims.
- **Audit durability is the host's.** The ledger is an in-memory substrate with no replication, no anchor of its own and no external checkpoint authority. `gateHighRiskEffect` is a pure structural check, which is exactly why the value passed to it is the one `appendAuditEvent` returned, in this process. This executor records the two `ALLOWED` decisions of the accepted path and one `DENIED` decision for the two attributable refusals above; privacy-safe evidence for every other refusal stays the integrating host's obligation, as does front-door enumeration control and any authentication behind these records. The stream congruence binds the substrate by the tenant/project it declares and by nothing else: this module cannot verify that the object bound to the executor really is that tenant's stream, that its keys are that tenant's keys, or that a committed entry survives the call.
- **Overwriting owned buffers is hygiene, not zeroization, and the backend's half is unproven.** Copies held inside native crypto, garbage-collected buffers and swapped pages are not covered by this module. This executor can only prove that the buffers **it** created are overwritten in its `finally`; the mandatory nonretention duty stated above - the backend does not retain, copy, log or forward the recovered bytes - is a host obligation that nothing here can observe, verify or enforce after `lookup` returns. A backend that copies the plaintext keeps a live copy the executor cannot reach or clear.
- **Not a protected-egress claim.** No byte leaves this process. There is no transport, no KMS/HSM binding, no production vault, no transaction, no lock, no retry, no recovery and no rate limit here.
- **Not acceptance.** [Slice 2](../specs/slice-2-vault-and-reversible-identities.md) stays a draft and [decision 010](../decisions/010-separate-information-dimensions-and-task-fidelity.md) is **proposed**; nothing here adopts a proposal or changes classification v1, policy or any adapter.

## Verification

```text
npm run build && npm run typecheck && node --test test/mapping-use.e2e.test.mjs
```

Twenty-eight cases in one file over one explicitly ephemeral in-process scenario. The observable counters are the host's own `authority` callback, its `material` callback, its backend and the audit ledger; the file makes **no** claim about calls the executor makes into `openMappingPayload`, because that call is internal to the shipped module - a `USED` or a `NOT_FOUND` proves the opener ran, because the only route to the backend is a recovered identifier, and a `WITHHELD` proves only that the backend was never spent. One case constructs an executor, replaces the bound backend's `lookup`, and then calls `use()`: the assertion is that the method bound at construction ran once and the replacement never ran, with a control where the same replacement was installed before its own construction and did run. One case changes a structurally valid classification record to another valid record that the same bundle selects `KEEP` for, and shows the original pin withholding while the matching pin spends: the refusal is the pinned digest, not an invalid record and not the lifecycle. One case spends a backend call the registry reports as `ACTIVE` at the instant of the call and then proves the queued revocation really landed afterwards, so the assertion is that any spend happened while the record was live, not that every queued revocation cancels an effect that already completed. One case replaces the live audit actor at the fourth observation with a proxy whose key enumeration throws, and shows `WITHHELD` with the backend never called and both decisions already recorded - the fault lands inside the sealed segment and is still a guard - with a control that makes the same replacement with a congruent plain actor and spends. Three cases cover [refusal evidence](#refusal-evidence): the missing, expired and revoked refusals each record exactly one `DENIED` decision with the established actor, the bound scope and no reference or identifier anywhere in the stream, while a foreign scope, a substituted audit actor and a ledger that cannot commit record nothing and a genuine accepted run still records exactly the two `ALLOWED` decisions. Two further cases cover the bindings those two guards depend on: a genuine tenant-A host - registry, authority, scope and actor - handed a genuine tenant-B ledger plus a matching tenant-B context, withholds on both the `ALLOWED` and the `DENIED` path with zero ledger entries, zero material callbacks and zero backend calls, with a control proving that same foreign stream really does commit through the real append, and an accepted run on the identical host still spends its own private resource; and a `FOUND` answer whose metadata is `null`, empty, missing its scope, carrying a state outside the lifecycle vocabulary or belonging to another scope withholds with zero entries and no lifecycle denial, while the genuine in-bound `CREATED` and revoked records still record theirs. `npm run check:fixtures` and `npm run check:docs` are the repository guards.
