## Material limits

### Scope-bound configuration handles

`createCandidateConfig` and `createContactSensitivity` capture each tenant/project label once inside
existing error containment, validate the captured primitive values and bind those same values to the
private handle. Later getter/Proxy answers or caller mutation cannot retarget that stored scope.
Ordinary, null-prototype and inherited scope properties remain supported; finite throwing reads
produce fresh fixed TypeErrors without forwarding the caller's exception. This is a pure snapshot
property, not authentication, an atomic-world snapshot, preemption of a nonreturning getter,
array/entry snapshotting or whole-constructor safety.

### Pure core seams and host-backed runtime effect owners, and what neither proves

The modules above fall into two kinds. A **pure core seam** is **evidence for a seam, not a
protected-egress boundary**: it authenticates nobody, sends no bytes and persists nothing durable. A
**host-backed runtime effect owner** reaches one local effect the host handed it, and its limits are
written against that effect rather than against the module in general. Neither kind proves anything
it does not own:

- No caller, subject, workload, `inputRef`, policy handle, destination profile or registry entry is authenticated. Trusted inputs are trusted because the trusted integration supplies them, not because the module verifies them.
- A `COMPLETE` result means no budget was exceeded. It never means "clean", "safe to send" or "policy allows".
- `PARTIAL`, `FAILURE` and typed refusals keep uninspected content **opaque**. Treating one as a pass inverts the fail-closed rule in [decision 007](decisions/007-fail-closed-for-protected-egress.md).
- The optional sentinel process wrapper ([`src/egress-sentinel-process.ts`](../src/egress-sentinel-process.ts), [contract](contracts/egress-sentinel-process.md)) is the one module here that **starts a local child process**; bounded local IPC still sends no bytes and authenticates nobody, its child runs with ordinary host permissions rather than any sandbox, and no heap, RSS or swap erasure is claimed. Full limits in its contract and module header.
- The text sender ([`src/openai-text-sender.ts`](../src/openai-text-sender.ts), [contract](contracts/openai-text-sender.md)) is a host-backed effect owner that **trusts every host input it is handed** and authenticates none of them. Its dispatch-point re-reads are congruence checks, not authentication; it cannot prove an arbitrary injected transport honors its contract, and a bypass around it is untouched. Its evidence is a synthetic loopback capture, not a deployed interception point. Limits in its module header.
- The KEEP-only receiver ([`src/openai-keep-receiver.ts`](../src/openai-keep-receiver.ts), [contract](contracts/openai-keep-receiver.md)) **trusts every host input it is handed** in the same way and makes **no host authenticity claim**: the boundary, profile digest and proofs are consumed as supplied, never re-authenticated. It cannot prove an arbitrary injected release point honors its contract, so its evidence is an in-process release capture, not a delivered model context. Provider source trust is pinned `UNTRUSTED`, and model text or token-shaped strings grant no authority. Limits in its module header.
- The bounded local conversation owner ([`src/openai-local-conversation.ts`](../src/openai-local-conversation.ts), [contract](contracts/openai-local-conversation.md)) composes the two owners above over one captured literal `127.0.0.1` socket, so it is the first module here whose bytes leave the process. That is a narrow loopback endpoint, not a provider: no host name, no URL, no name resolution, no TLS, no proxy, no redirect, no retry. It inherits both hosts' trust boundaries unchanged and adds no authentication, so it is **not** a protected-egress boundary and covers no path around it. Limits in its module header.
- The bound `USE` executor ([`src/mapping-use.ts`](../src/mapping-use.ts), [contract](contracts/mapping-use.md)) is a **runtime coordinator that owns one guarded private effect**, not a pure seam: the effect stays local — it authenticates nobody, sends no bytes and persists nothing durable — so this is **not** a deployed or authenticated broker or vault. Its identity, route, grant, key version and clock are a **host honesty obligation**; key custody, snapshot coherence across concurrent executors, audit durability and zeroization of a backend-retained buffer are host obligations or unproved limits, and `USED` means exactly that one private synchronous resource answered with a boolean. Detailed limits in its module header.
- The bound revocation owner ([`src/mapping-revocation.ts`](../src/mapping-revocation.ts), [contract](contracts/mapping-revocation.md)) is a **runtime coordinator that owns one guarded metadata mutation**, not a pure seam: a `revoke()` that reports `REVOKED` has driven the shipped registry compare-and-set and recorded two real `MAPPING_LIFECYCLE` events, reaching no plaintext and no key. Revocation authority is a complete closed administrative decision the host supplies, which this module checks for congruence and currentness but cannot authenticate, and no `USE` grant can authorize it. Any unconfirmed outcome after an attempted mutation is `UNRECORDED`, whose completion is **unknown in either direction** and which rolls nothing back, claims no audited success and revives nothing. Limits in its module header.

### No adapter sits at a real send point

There is no transport interceptor, no vault, no authorization broker, no KMS/HSM binding and no runtime-enforced Policy Engine in this repository. Concretely:

- The [Egress Sentinel](#assurance-governance-and-release-seams) is a core with **no adapter at a real send point**. It has never decided a byte a provider actually received, and [`src/adapter-conformance.ts`](../src/adapter-conformance.ts) only proves a *candidate adapter* behaves against a synthetic controlled capture.
- The text sender, KEEP-only receiver, bounded local conversation owner and local-capability listener have effect paths over trusted hosts and synthetic loopback peers, alongside the bound local mapping effects above. ### Resource bounds are per process

Parser time budgets are cooperative and read from a host-owned clock. Research sandbox limits are per process (and per real UID), so no aggregate memory, CPU or process bound exists without privileges. A budget is not a cause: this repository records unattributed intermittent full-run failures without inferring or excluding a cause, and no budget was raised to accommodate one.

- `rewriteFieldValues` in [`src/structured-parsers.ts`](../src/structured-parsers.ts) snapshots the shared options, reads each edit's span and replacement once, and returns `{status: 'FAILURE', reason: 'REWRITE_ERROR'}` with no text, exception detail or partial output on a finite caller-side throw, so a getter that throws or answers differently later cannot change the rewrite halfway through. That boundary is **not** authentication and **not** a freshness check, and like the cooperative budget it cannot preempt a getter or callback that never returns. Limits in the module header.
