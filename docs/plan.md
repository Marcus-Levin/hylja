A bounded, **NON-ENFORCING** #19 egress sentinel core exists in [`src/egress-sentinel.ts`](../src/egress-sentinel.ts). It checks exact outbound bytes independently of the #8 detector stack:
- known planted originals and canaries, held only as keyed fingerprints. Long values are matched after separators are stripped, and short values against windows of whole consecutive tokens (so `Or la`, `o r l a` and `10.0.0.1 x` match, but not text inside a longer word). Both sides are folded for compatibility, case, marks, invisible characters, common Cyrillic/Greek/Armenian homoglyphs and leading zeros in every digit run. Keyed prefilters plus capped HMAC verifications and prefilter probes keep work bounded;
- its own high-risk pattern set, tested on raw and compatibility-normalized case-preserving text; credential assignments ignore references, type names, booleans, member expressions, a bare identifier that repeats its key (`{ password: password }`), whole quoted branch labels of a conditional (`? 'SECRET' : 'INTERNAL'`) and `PWD` values starting with `/` or `~`; URL passwords (including an empty user name, `redis://:password@host`) ignore only whole placeholders (`${password}`, `{{password}}`, `$DB_PASS`, `%s`, `<password>`);
- canonical views: #6 decoded views (including printable strings of binary decodes), its own escape decoding (JSON/JS/Python `\U`/octal/CSS/`%u`/HTML entities/quoted-printable) iterated to a bounded fixpoint, byte-valued views of contiguous escape runs and quoted Latin-1/byte strings, and printable-byte views of short encoded binary runs. When the scope registers short originals, a separate bounded, match-only pass checks Base64/hex alphabet runs of 6–15 characters (plus optional padding) and their tentative decompression; it does not add opaque-byte counts, though a signed nested container still blocks;
- a destination/profile assertion read once, and tenant-scoped handles that must be passed explicitly (`null` for unprotected egress).

The following all `BLOCK`:
- invalid UTF-8;
- uninspectable (#6 PARTIAL) content;
- a known original, canary or high-risk pattern found in any decoded view. Beyond #6 and the escape views, the sentinel rebuilds encoded data that was split up: Base64 or hex in chunks separated by whitespace (any amount, including indentation and pretty-printed JSON arrays), commas, quotes, brackets, JSON `\n`/`\r`/`\t` escapes or `:;|.&`, with plain words between chunks dropped; hex split by `-`, `_` or `/`; byte pairs (`63:6f`, `63 6f`, `0x63, 0x6f`, JSON/YAML arrays of pairs, `xxd -g1`/`xxd -i`/`hexdump -C`/`od` dumps, whose offset and ASCII columns are dropped); and default `xxd` two-byte groups with offsets and ASCII columns. A prefix that misaligns chunks (a digest or word glued before them) is also tried without it. Escaped byte runs of four or more bytes (`%xx`, `\xNN`, `\u00NN`, octal, numeric HTML entities, quoted-printable and caret controls) and mixed quoted Latin-1/byte strings are also reconstructed. Out-of-range three-digit octal escapes block as uninspectable. Binary layers reached through these representations are decompressed: gzip/zlib with a signature in the first 16 bytes of a run, of the concatenation of runs or of a later run, or anywhere inside a run (first 256 signatures, for matching); brotli and raw deflate at the start. Nested layers are followed up to four deep and streams after a stream's end, including empty ones, along a chain of up to 256, within a 4 MiB per-message output budget. Text layers are matched and decoded further, including text found under brotli/raw-deflate output that may be accidental (decoded but not counted); binary layers are matched as printable bytes and as UTF-16 but not decoded further. This precise-reason guarantee is verified for the forms listed here, not for arbitrary custom encodings, and a message already blocked as opaque may report only `OPAQUE_EMBEDDED`;
- embedded opaque binary, as a **best-effort heuristic**, not a completeness claim. Container formats (zip, bzip2, xz, 7z, zstd) block outright when visible in encoded bytes or under a signed gzip/zlib layer. A container signature reached only through tentative brotli/raw-deflate decoding is not by itself an opaque-content finding; a successfully decoded signed gzip/zlib layer nested beneath it still blocks as opaque. More than 32 bytes in total per message, across all views, of binary that looks encoded blocks: long Base64/hex runs, clearly encoded short-chunk sequences, equal-group separated hex, binary gzip/zlib output and bytes after the end of a stream. Not counted: unbroken exact-length digests and 64-bit/object ids in hex; algorithm-matched exact-length digests in `shaNNN-`/`h1:` or digest context (SRI, go.sum, Content-MD5), plus MD5-length ETag values; UUIDs; structurally valid standard-Base64 SSH ed25519 public-key blobs; lines of a PEM certificate or public key whose body is one DER SEQUENCE of exactly its stated length (real or JSON-escaped line breaks), the Base64 alphabet, identifiers and paths made of words and numeric ids, decimal numbers, MAC addresses, and hex lists (fingerprints, hashes, ids). Random tokens and session ids block, since in protected egress they are credentials themselves (decision 009);
- oversize messages;
- an exhausted view or verification budget;
- errors and outage.

Payloads dense with long alphanumeric identifiers can exhaust #6's decode-work budget and therefore block. A streaming gate holds the complete message and releases nothing before the check. ALLOW returns a private copy of the checked bytes. Results and regression records carry codes and refs, never bytes or values.

Known limits:
- a short value glued into a longer word (`OrlaSmith`) is not matched; the short-encoding pass checks only whole Base64/hex alphabet runs of 6–15 characters (plus padding), when short originals are registered, and blocks if more than 8,192 distinct tokens need inspection;
- confusable coverage is a small table, not full UTS #39;
- only the listed escape families and a few named HTML entities are decoded;
- a bare short base64 DER body without a header or known value passes the pattern set;
- binary disguised as recognized digests or ids (hex runs of digest or id length, UUID-shaped) is not counted; a digest context exempts only the decoded length of its named algorithm. A syntactically valid SSH ed25519 public-key field still cannot prove that its 32 key bytes were not repurposed as opaque data. A PEM body only has to be DER-shaped, so random data behind a matching length header is not counted; base32 is not decoded; quoted-printable is decoded only in runs of two or more escapes;
- a random token that happens to split into word-like segments (roughly 0.1% of 30-byte Base64 tokens without padding) reads as an identifier and is not counted; comma-separated lists of short digit-heavy camelCase names (`UTF8ToUTF16LE, UTF16LEToUTF8, …`) can count as opaque;
- the advisory-suffix identifier exemption accepts only short path words (including capitalized, CamelCase and underscore-separated words) or numeric components of up to four digits; repeated slash components are treated as encoded data and never identifier-exempt beyond an optional leading URL `//`, with advisory or generic suffixes and after percent or Unicode escape decoding. Longer or mixed alphanumeric paths may block as opaque even when they are legitimate;
- the opaque-binary count misses uncompressed random data in several ordinary-looking shapes: Base64 in chunks of about 8 characters or fewer, hex chunk and byte-pair lists, chunks joined by `:;|.&`, and brotli/raw-deflate output that could be accidental. Such data passes unless it holds a known value or pattern;
- encoded data is not rebuilt from chunks with labels (`part1 …`, `p1: …`), chunks joined by other punctuation (` + `, ` / `, ` > `), arrays of JSON objects, decimal byte arrays or Node `Buffer` JSON;
- escaped bytes split across labels or punctuation, bare escape runs shorter than four bytes, unsupported mixed escape syntax, and multiply serialized Latin-1 strings may be blocked as opaque without a precise known-original finding. Unicode and HTML escapes of ordinary accented prose are inspected but do not add to opaque-byte counts unless they contain control bytes; this can miss binary made solely of high Latin-1 bytes. Opaque counting remains best-effort;
- brotli and raw-deflate streams are found only at the start of a decoded run or of a stream's remainder, and gzip/zlib streams deeper inside a run only for matching, so a brotli/raw stream behind other bytes, including inside a DER-shaped PEM body, is not decompressed. Brotli/raw-deflate output is tentative: it and nested layers are inspected for known values and patterns, but cannot independently raise or lower the opaque-byte count; a short unsigned stream holding unknown opaque data can pass;
- a single short default-`xxd` row is not rebuilt; two or more rows with at least 16 reconstructed bytes are required, and uncompressed opaque data in hex lists remains a count gap;
- credential assignments flag bare identifiers other than the key itself (`secret: required`, `Password: pass`), because unquoted passwords look the same; a `PWD` value starting with `/` or `~` is never flagged, whatever follows;
- a 1 MiB adversarial message of many small compressed streams as hex pairs can take about 4 s to check;
- byte arrays that spell a container signature (`0x50, 0x4b, 0x03, 0x04, …`) block, including this module's own signature table;
- unquoted dotted credential values (`password=Synthetic.Passw0rd`) read as member expressions and are not flagged by the assignment pattern;
- short values match on whole-token windows, so prose like `or la` can match a short entry `Orla` and block.
- dense source text can exhaust #6's decode budget and block (seen on 2,000-character chunks of this repository's own detector sources). **Not yet integrated**: no adapter calls it at a real send point, #13 transformation does not exist, the #11 judgment seam exists but is a local/synthetic-only non-enforcing module that nothing calls and that has no external path (see the #11 paragraphs below), and the #37-to-egress text slice has not run end to end.
