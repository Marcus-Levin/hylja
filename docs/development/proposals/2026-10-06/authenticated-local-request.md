## Observable next proof, not a gateway rewrite

Recommend first proving **one actual synthetic mTLS client connection** authenticated by a server-owned native event, mapped through independently provisioned enrollment to one canonical workload, with live expiry/revocation refusals. It sends no upstream traffic, supplies no `BoundaryContext`, selects no policy treatment and releases no model response. An isolated authenticator test may emit one fixed non-protected acknowledgement only in response to a fixed bounded non-protected client application probe received after `secureConnection`, never immediately on handshake completion. This gives an observable window for revocation/expiry between handshake and probe; the probe grants no identity, context or effect authority. This is not source-only authentication evidence once executed; until then it is entirely untested design.

The defect to avoid is concrete: #261's capability permits access only; all eight static proof windows expire. Rebuilding #236 from the same fixture does not authenticate a workload or establish new request/source/route observations. Human approval of an authenticator alone must not be read as admission of a renewal loop, generic inspector or gateway integration.

### A — Native connection authenticator (the next executable unit)

Suggested exclusive files: new `src/local-workload-authenticator.ts`, new `src/node-tls.d.ts` for only verified used built-ins, new `docs/contracts/local-workload-authenticator.md`, new `test/local-workload-authenticator.e2e.test.mjs`, and narrowly admitted synthetic fixture/support paths. Do not edit listener, conversation, envelope, sender, receiver or policy. No JWT/SPIFFE library, CA service, secret store or dependency addition.

**Admission prerequisites:** human decision 014 choice 1; inspected pinned Node TLS/X509 APIs and narrow declaration design; reviewed offline synthetic certificate provisioning/provenance and custody procedure. Default future tests to ephemeral in-memory key generation, with nothing tracked, following the ephemeral-key precedent of `npm run check:release`. Node's key generation alone is not an X509 issuer; issuance/provisioning remains unresolved. Do not run OpenSSL/other binaries, add a package or commit private material to bridge that gap in this task. The live issue must name the approved fixture mechanism and make it reproducible on CI, including valid, expired, untrusted and mismatched-private-key controls. The current `scripts/check-fixtures.mjs` rejects tracked `.pem`, `.key`, `.p12` and `.pfx` paths everywhere and private-key PEM markers in every fixture area, including `test/fixtures/synthetic-golden/`. Its synthetic-assignment exemption does not admit private-key material. Any tracked private-key proposal requires a separate reviewed guard-policy decision outside this task; re-encoding, renaming, private-JWK fields or any other representation to evade detection is forbidden. No future fixture stub counts as passing evidence.

Proposed closed construction shape: one numeric-loopback listen port, explicit trust-anchor/server-credential material, fixed TLS profile, and independently enrolled registry owner. Credential input copies capped at 65536 bytes per field, at most one anchor and one server chain of at most four certificates; at most 16 enrolled leaf records. Parsed leaf DER capped at 16384 bytes. Over-cap post-handshake refusal alone is not a native handshake memory bound: native pre-parser resource bounds must be established or reported unproven. Labels are nonempty ASCII opaque identifiers <=256 bytes without controls; SHA-256 pins are 64 lowercase hex characters; times are finite canonical UTC values; revisions are positive safe integers. Unknown keys, accessors, symbols, sparse arrays, malformed times/keys or noncoherent records refuse with fixed non-echoing codes. Snapshot bounded own data once; do not infer identity from any certificate string field.

Proposed public lifecycle: `start()`, idempotent awaitable `close()`, readonly state. The native `secureConnection` handler enrolls the real socket in private storage; no public `authenticate(socketLike)` or JSON credential constructor. A test/internal handoff may expose an opaque, nonserializable handle to B, with no key, certificate, subject-authority constructor or releasable bytes. A private `current(handle)` checks that exact socket, certificate validity, enrollment revision/availability lease and sticky cancellation. Handle objects fabricated in a different owner or reused after close refuse. No effect capability is returned by authentication.

Registry records contain exact leaf digest, canonical principal/workload and enrolled/revoked state, issue/expiry, revision; they do **not** contain tenant/purpose release grants. The independently provisioned registry has at most 16 records, coherent synchronous current reads and a <=300000 ms availability lease. It exposes only separately bound operator changes; the network client cannot call them. New enrollment/rotation is explicit, never auto-created by an unknown valid certificate. Any malformed/outage answer refuses. The acknowledgement trigger is the post-handshake bounded application probe, not `secureConnection` itself. Unit A's live brief must pin the exact probe/ack frames, absolute read bound, once-only `Ack` counter and synchronous last-guard/captured-native-write behavior; test revocation/expiry after observed handshake and before sending that probe. No async current lookup, callback or await may be placed between final live check and acknowledgement write; a future remote authority would require a separately reviewed lease/coherence contract.

Native options require requesting/rejecting unauthorized certificates and explicit CA pinning. Use the actual completed handshake plus `authorized` and usable peer X509 certificate. Disable renegotiation; reject resumed sessions and unsupported TLS/ALPN profiles rather than inheriting older authentication. No trace/keylog/native-error logging, early data or permissive fallback. The exact version/option/method shapes, certificate validity extraction and resumption refusal behavior must be proved, not guessed from these conceptual requirements.

Bounds: four accepted/pending sockets, five-second absolute handshake deadline, no queue; one connection lease <=five minutes and no later than native certificate or enrollment expiry. Closing cancels all pending/live handles, destroys sockets, closes server and awaits observed close events. Malformed host opens nothing; invalid credentials receive no application acknowledgement. Finite operator callbacks are trusted code; no timer can sandbox a callback that never returns. Native encrypted handshake bytes may exist on the inbound client link on refusals; distinguish them from protected application bytes.

**Focused gate after red behavior checkpoint and build:** `node --test test/local-workload-authenticator.e2e.test.mjs`. Positive requires real synthetic credentials on a real loopback TLS socket, independently declared expected principal mapping, exactly one fixed acknowledgement and actual socket closure. Refusals require zero acknowledgements and zero protected client bytes; changed registry values must be tested during the connection before the probe, not only at construction. A proves native credential/principal/handle and `Ack` outcomes only. Zero upstream connections/bytes is an architectural exclusion because A opens no upstream, not discriminating egress evidence; C must prove actual guarded wire.

### B — Request-evidence provider (no transport or authentication)

Suggested exclusive new files: `src/local-request-evidence.ts`, `docs/contracts/local-request-evidence.md`, `test/local-request-evidence.test.mjs`. Requires A's actual opaque handle contract and P's accepted handoff. It authenticates no socket, opens no connection, classifies nothing and performs no release. It must reject fabricated, foreign or stale A handles and arbitrary public proof-shaped objects.

Conceptual input is a privately enrolled authentication handle, owned bounded canonical request observation, independently provisioned authority record, and direction-specific controlled adapter observations. Output is one private once-only request record plus sender/receiver `BoundaryContext` snapshots for the respective stage and captured live-guard methods. A shape valid to the envelope is not itself provider enrollment. Snapshot boundaries without extending an in-flight window; receiver records cannot be constructed before reply observation. Both direction identities/contexts remain equal; sources and destinations are distinct.

Authority record: exact subject, tenant/project membership, server-assigned session/purpose, `SEND` grant, policy id/version/digest, two profiles and numeric upstream endpoint; <=16 records, <=256-byte identifiers, exact closed own-data schema, one current revision/lease, no default profile. Bundle/profile data are validated by existing policy readers; the independent control plane supplies the pin, not a hash copied from client configuration. Source trust is independently bound; receiver trust remains `UNTRUSTED`. Maximum request/reply observation is 65536 bytes each; private SHA-256 digest and generated request id; at most one active request, no queue, one dispatch and one release flag, proof refs <=256 bytes. Explicit canonical timestamps follow envelope's <=five-minute limits and intersect certificate/enrollment/grant/policy/profile/observation leases. Closing/cancellation/expiry/revision change is sticky for that record; no reissue or renewal during its use.

A new request can get evidence from a new actual request observation while existing independent authority remains current. Fresh timestamps alone never create grants, source trust or a route. A normally closed upstream socket after a complete reply retains only its observed response binding; it cannot authorize another dispatch. Outage/missing/revoked/stale observations deny before the next effect. Profile digest derivation must use the separately provisioned committed profile representation with a pinned canonicalization convention, admitted in B's exact brief; never guess the test fixture's hashing convention.

**Focused gate after build:** `node --test test/local-request-evidence.test.mjs test/interaction-envelope.test.mjs`. Include coherent positive records, tenant/project/session/purpose variations, cross-owner and replay/context swap, independent origin outages, all eight stale intervals and phase ordering. Property cases must vary one binding at a time against independently declared expectations. Unit-double provider tests prove validation only, not authentication, wire safety or real route discovery; C must rerun them through actual A/transport observations.
