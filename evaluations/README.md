# Public development smoke adapter interface and limits

`public-development-adapter.mjs` is an **exploratory, unscored, synthetic-only, evaluation-only, NON-ENFORCING** bridge from the already landed deterministic/no-Jev reference to the #5 `runCandidate` / in-memory sink contract. It is neither a second scorer nor a frozen protocol, production adapter, actual-route witness, Policy Engine, authorization rule, broker, #19 independent sentinel or safe-send assertion. `TRANSFORMED` is an untrusted candidate observation, **not** release permission. See [the implementation plan](../docs/plan.md#current-state) for implementation status; the public [fixture/rubric proposal](../docs/research/issue-39-public-rubric-p0.1.md) remains non-normative.

## Evaluator-facing seam

Build (`npm run build`) before importing, since the ESM adapter uses #5's compiled classification vocabulary. `projectPublicDevelopmentFixture(fixture, localSink)` snapshots **only** public D01 `input.text`, individual D02 `input.lines` or D05 `input.value` and optional `taskControl.prompt`. The evaluator supplies `{ id: 'CAPTURE-DEMO-MODEL', profileId: 'EVAL-LOCAL-...' }` independently of fixture-proposed route/profile. The projection exposes an immutable `developmentCase` with `field-0`, `field-1`, ... refs and an evaluator-only `fieldRefForSourcePointer('/input/...')` lookup. It does not read fixture route proposals or task expected answers. D05 is one deterministically key-sorted, bounded JSON string field (`/input/value`); the adapter's `fieldRefForSourcePointer` still maps the whole field only. A separate evaluator-private, raw-source-verified span projector is documented below; it does not change the adapter or candidate-facing fields. Hints and native JSON keys, where needed to perform the visible config task, are content, never field IDs, source authority or separate candidate metadata.

`runPublicReferenceCandidate({ projection, evaluation, capture, oracle, observeLocalSink, candidate?, serialize? })` snapshots the evaluator-owned oracle's top-level own data descriptors once and registers that **same** copy with #5 before invoking `runCandidate`; #5 alone validates nested planted content before any candidate callback. The candidate receives only `{ sinkId, fields: [{ id: 'f0', text, hint? }, ...], taskPrompt? }`: no profile, fixture refs, source paths, oracle labels/values, expected answers or proposed route. Candidate events are checked as bounded UTF-8 byte spans (boundaries computed once per field, not once per event), then converted to #5 `field-0` refs. Candidate disposition, event fields, transformed fields and optional task result are **all** validated *before* invoking controlled `send`: #5 by itself permits `send` before validating a callback's returned events/task result. D05 transformed field text must parse as a JSON object; an optional D05 task response must parse as an object with the public config's eight correctly typed fields. This is an **exploratory DEV-only pre-send structural check**, added after the public fixture/reference exposure: it is not an approved destination policy, task grader, frozen rubric, 443/HTTPS/path/OS/timeout grade or privacy check. The independently configured evaluator grader retains task semantics. `BLOCK`, absent/mismatched local observation, unsupported input, malformed output or serializer failure result in no adapter send and no task result. Generic errors do not echo source content. A missing capture remains #5 `untested/no-capture`, not a safety pass.

The evaluator owns `observeLocalSink()` and must actually supply a matching local sink/profile observation independently of the fixture (checked initially and again immediately before serialization). The default `serializeControlledRelease` deterministically encodes a JSON body containing final transformed ordinal fields and a JSON metadata record containing local sink/profile/surface/representation, **both as UTF-8 `Uint8Array`s**; those exact final arrays are copied into #5's controlled sink with no adapter mutation afterward. There is no socket, HTTP request, authorized egress or unobserved stream. Optional `candidate` and `serialize` overrides are evaluator-owned *adversarial test hooks*, not candidate authority; a test-specific independent planted control can establish that a deliberate leak in **either** captured body or metadata fails in #5 despite empty/false candidate events. The adapter does not compare against oracle records itself, intercept production traffic or suppress a test-induced leak.

The evaluator must call `evaluation.clear()` and `capture.clear()` after producing any report, and drop projection, fixture, candidate and byte-array references; otherwise even synthetic originals and captured bytes remain in process memory. Do not persist raw captures, maps, prompts or planted values in ordinary logs/reports.

## Evaluator-private D05 raw-source span interface (development only)

`d05-canonical-json-spans.mjs` exports `D05_CANONICAL_JSON_SPAN_VERSION = 'd05-canonical-json-v1'` and `createPublicD05SpanProjector({ rawFixtureUtf8, projection, fixtureId: 'D05-DEV-001', sourceValuePath: '/fixtures/2/input/value' })`. The **actual entire raw public fixture JSON** must be supplied as bounded `Uint8Array` bytes; an already-parsed object, a string, absent bytes or an unbound value fragment cannot establish raw duplicate-key absence. Its bounded pre-parse token walk checks JSON grammar, strict UTF-8, unique **decoded** keys (including escaped aliases) at every object, no lone surrogates, one D05 id at index 2, and the exact input/value pointer. It compares its independently reconstructed `JSON.stringify`-style sorted eight-key field byte-for-byte with the frozen adapter projection's `field-0` content; serializer drift rejects, not silently reprojects. A caller able to fabricate both raw fixture bytes and the adapter projection is **not authenticated as a file-origin witness** by this pure self-consistency check. Scored file provenance requires a separate trusted custodian and pinned original-file digest before this API; neither is supplied here. Do not treat the receipt as a signed fixture identity, scored-ingestion proof or approval.

The returned frozen object exposes `version` and `projectSourceOccurrence({ fixtureId, path, sourceSpan: {start,end}, normalizedSpan: {start,end}, sourceOriginalText })` for independently authored, evaluator-only source controls. The source offsets are zero-based **half-open Unicode code-point** indices in each *decoded string leaf*, not fixture-file offsets. This v1 accepts identity normalization only (`normalizedSpan` equals `sourceSpan`), validates the exact decoded substring, and maps key/path identity through the actual canonical JSON field's token boundaries, never a global occurrence search. The output is only `{fieldRef:'field-0',start,end,value}` with half-open **UTF-8 byte** offsets and the exact raw serialized field substring. For this ASCII-only first slice decoded and serialized spellings coincide; the source truth remains inside the evaluator-private projector for future, separately reviewed equivalent-encoding checks. Never add native source paths/keys, proposed routes/profiles, oracle labels, treatment/answer or this projector object to candidate input. An evaluator may explicitly combine *test-authored* returned entries with independent #5 oracle metadata to register synthetic controls; this module neither performs registration nor grades/tunes any candidate, and **does not load the official public oracle**.

The only occurrence-bearing D05 leaves are **whole** decoded `customer`, `project` and `outputPath` leaves, plus URL `endpointUrl` **HOST substring only** (not scheme, port, route or the whole URL). Truthful partial subspans of the three whole-leaf controls are not additional planted occurrences and reject. Numeric `port`/`timeoutMs` have no string spans; `protocol`/`os` are not planted occurrence paths here. Strict supported input is the public eight-key flat JSON value (six nonempty unescaped printable-ASCII strings and two nonnegative canonical safe integers no greater than 1,000,000), unescaped ASCII keys, bounded `https://` `.invalid` host URL syntax; it does **not** classify other fixture shapes or choose treatments. Reject/mark **unsupported or untested, not passed**: any D05 escaped key/value (even harmless `\u` or aliases), non-ASCII key/value, nested object or array value, integer-like/extra/missing keys, quote/backslash/control characters in D05 strings, decimal/exponent/negative/oversize numeric forms, userinfo/percent-encoded/IPv6/ambiguous URL hosts or empty/dot/double-slash route segments, partial whole-leaf spans, unmatched source path/fixture, nonstring leaf, invalid/fractional/zero/out-of-range source offsets, inconsistent normalization, changed source truth, missing raw bytes, malformed/oversize/deep or duplicate-key fixture JSON, malformed UTF-8 and lone surrogates. Bounds: whole raw fixture at most 131,072 bytes, JSON depth at most 16, at most 2,048 parsed value nodes; D05 leaf at most 4,096 characters; canonical field at most 65,536 bytes. Generic errors echo no content; drop raw/projection/projector references promptly. Escapes in *other* public fixture fields can be parsed solely to detect decoded-key duplicates and are not evidence for projected D05 escapes.

## Non-claims and remaining threats

- The adapter's D05 `JSON.parse` structural task check still collapses duplicate keys in independently supplied **candidate output** and is not a complete JSON-fidelity guarantee; the separate raw-source projector proves only its declared evaluator input subset, not output safety. No original public DEV oracle file is loaded or scored by these tests; they use independently authored, test-specific synthetic controls. The D05 task check is based on the candidate-visible transformed config/prompt and a separately registered test-only task control, not a raw-original answer.
- D02's visibly nonlive credential causes the reference candidate to `BLOCK`: the adapter attempts no send and the task remains unsolved; sink escape is **untested**, not an independently verified zero-byte denial. It does not establish agreement with any destination-specific proposed `MASK` treatment, policy correctness or successful utility.
- The configured local callback/profile can be fabricated by a caller; this module cannot authenticate a real principal, observed external route, approved destination, scope, required policy or sentinel. Deliberately bounded supported public inputs reject unknown formats, getters and malformed JSON representations; bypasses/opaque content and non-tested surfaces receive no inferred pass. The deterministic reference has regex/field-shape misses and no general transformed-content safety proof.
- The reference candidate predates a formal #39 pre-tuning treatment/task/rubric lock. These are **exploratory DEV smoke observations**, never a retroactive baseline lock, scored v0 eligibility or #40–#47 comparison. Freeze a separately reviewed baseline and snapshot candidate head before future blind work; do not use this bridge to tune against independent oracle labels or any held-out material.

## Public preparation integrity interface (nonlocking)

`node evaluations/preparation-integrity.mjs` takes **no arguments**. The ESM `verifyPreparation()` likewise takes no inputs or file selectors and returns only `{ status, reason }` from fixed codes. An intact, tracked, unchanged public draft returns `PREPARATION_VALID_BUT_NOT_ELIGIBLE / PUBLIC_DRAFT_ONLY`; failures return `PREPARATION_INVALID` with a fixed reason code, never a path, value, hash, seed or Git stderr. `requireScoredV0()` unconditionally returns `SCORED_V0_DENIED / EXTERNAL_APPROVAL_BOUNDARY_ABSENT`, regardless of any supplied self-claim. The CLI exits nonzero for invalid preparation. The verifier explicitly selects only the fixed [draft manifest](../docs/research/issue-39-v0-preparation-draft-p0.1.json), public corpus prep, D01/D02/D05 fixture, separate public DEV oracle proposal and rubric, and open-gates packet; Git subprocesses may also read trusted repository metadata and configuration includes. The manifest's five SHA-256 values bind **raw public file bytes for reproducibility only**. Its `preparationSourceRevision` identifies a historical whole-repository Git snapshot; it does not pin a scored runner/config/candidate, establish pre-tuning chronology or authorize release. Public documents and manifest must be singly linked regular files with no symlinked parent/leaf; each fixed path's raw bytes must equal its Git HEAD blob, and each index blob ID must equal HEAD even when `assume-unchanged` or `skip-worktree` hides a modification from `git diff`. Git invocation ignores global/system configuration and replacement objects, overrides local fsmonitor and does not use diff drivers, hooks or content filters. An existing repository-local `info/grafts` file rejects the draft before source ancestry is checked; no graft content or metadata path is reported. Strict fixed-schema canonical JSON rejects extra fields, duplicate keys, approvals, restricted material claims and non-PENDING choices.

The script does not intentionally select, hash, traverse, enumerate, score or report private blind material; Git may parse repository-local metadata/configuration includes, so keep restricted evaluation stores inaccessible and run only with trusted Git metadata, not as a hostile-host isolation boundary. H01–H04 remain planning IDs only, with no digest/seed/location in the public draft. The reference is explicitly exploratory pre-lock/ineligible, D03/D04/D06–D12 are planning/untested, and the proposed D01/D02/D05 controlled text/JSON do not establish an observed external route, capture continuity, transport interception, #19 sentinel, policy grant or real isolation. Candidate `BLOCK` with no captured sink bytes is **candidate-block-observed, sink-escape-untested and task-unsolved**, not independently verified zero-byte denial or safety PASS. No candidate output, callback, grader or capture participates in preparation integrity. Git/worktree inspection and unkeyed hashes are local drift checks, not signatures, a hostile-concurrent-filesystem guarantee or an external custodian/approval boundary. Human scope, policy/treatments, independent task/rubric, blind custody and eligibility chronology remain PENDING; a separately designed, independently authorized pre-tuning lock and later final-v0 freeze must precede any scored comparison or #48 selection.
