# #39 deterministic/no-Jev reference candidate

This is an **evaluation-only, NON-ENFORCING** disposable candidate, not Hylja's Policy Engine, an evaluator, a production detector, a safe-to-send assertion, a broker or a final egress check. It uses only the reviewed public synthetic D01/D02/D05 development syntax. See the [implementation plan](../../docs/plan.md#current-state), [public fixture/rubric](../../docs/research/issue-39-public-rubric-p0.1.md) and [evaluation policy](../../docs/evaluation.md). It neither reads an oracle nor grades itself. No v0 hash, score or freeze follows from its tests.

## Candidate-facing interface

Import `runReferenceCandidate` from `reference.mjs` in Node >=22. Its entire input is `{ sinkId, fields, taskPrompt? }`, where `fields` is a nonempty array of `{ id, text, hint? }`; accepted hints are `text`, `json`, `person`, `customer`, `project`, `outputPath`. `text` is a UTF-8-representable JavaScript string, and `json` denotes one complete JSON text field; for JSON, a later evaluator adapter must establish its own pinned serialization before it creates that field. **Field IDs must be evaluator-minted per-case ordinal refs `f0`, `f1`, ... in array order (maximum 64)**, never copied from source keys, field paths, candidate text, fixture references or an untrusted request. An invalid or out-of-order ID returns `BLOCK` with no events or transformed fields. This shape check is not authentication or source authority. The sole recognized sink ID is the public *proposed* synthetic local-capture ID `CAPTURE-DEMO-MODEL`, not an observed destination or approved profile. Extra context/profile/expected-answer properties are rejected, never trusted.

Result: `{ disposition: "TRANSFORMED", events, transformedFields, taskResponse? }` or `{ disposition: "BLOCK", events, reason }`. Each detector event is `{ fieldId, startByte, endByte, semanticType, subtype? }`, using half-open UTF-8 byte offsets **in the original field text**. Events have no plaintext-value property, and their field refs are only validated ordinals; that does **not** establish the absence of planted originals in arbitrary candidate outputs or replace #5's independent final-byte check. The transformed fields retain these ordinal IDs/order, use irreversible generic masks, and have no original-value mapping or restoration operation. `taskResponse` is an optional JSON *string* for the narrow synthetic HTTPS config-edit prompt/shape; it is absent for other prompts and every block. `BLOCK` returns no transformed field text or task response. Both dispositions are candidate observations, **never release permission**.

## Future #5 adapter seam (illustrative, not a frozen API)

A future `runCandidate` callback must first mint `f0`... by indexing the candidate-visible fields in stable order; it must **not forward native keys/paths/refs as IDs**, and may keep only an ephemeral ordinal-to-field-position association for event conversion. It can project only candidate-visible field text, those minted ordinals, its declared controlled sink ID and task prompt into this function. The adapter would translate returned ordinal/byte-span events into #5's finalized event schema, without using candidate output to form planted labels. On `BLOCK`, it returns an abstention with no send. On `TRANSFORMED`, **the evaluator/adapter**, not this module, must decide whether/how to serialize and submit to its controlled sink, bind the *actual* route/profile from trusted observations, capture exact body and metadata bytes (including candidate-provided references), and grade against its independent planted oracle and task control. If binding, representation, serialization, required policy or check cannot be established, it must withhold the release. Do not feed proposed fixture profiles, planted values/labels, answers, held-out material, or candidate outputs back as authoritative context. No live or third-party traffic belongs in this seam.

## Measured limitations

The literal regexes cover only simple visible development-pattern NAME/EMAIL/fictional US PHONE, customer/project, synthetic host/documentation IP and obvious credential assignments or private-key markers. SECRET-looking evidence blocks the entire candidate even when visibly nonlive. D02 sans token preserves 443 vs 8443 and HTTPS `/health`; D05's plain JSON output path is irreversibly replaced by a valid absolute Linux `.json` path and its optional edit derives the requested HTTPS port from the candidate-facing prompt, retaining visible customer/project/host/path relations. Malformed JSON, **any backslash escape in JSON text (including Unicode-escaped keys that can create duplicate effective keys)**, an ambiguous/non-plain output path or an unsupported field shape blocks; this limited parser never emits a partly rewritten escaped JSON path. Text not recognized by these rules may remain unchanged **as a candidate miss**, not as proof that it is safe; escaped/encoded/nested variants, host collisions from a common placeholder, multi-entity identities, credential variants, adversarial fragments and contextual re-identification remain unsupported or unproved. Future independently authored #37 NAME/EMAIL/PHONE recall, false-cloak and actual sink escapes must be measured by #5, not inferred from these green tests.

Run only the scoped tests here: `node --test evaluations/candidates/reference.test.mjs`. The tests consume public synthetic input and assert behavior; they do not inspect oracle labels, score outcomes or simulate a controlled sink.
